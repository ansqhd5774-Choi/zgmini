### 2. 수행할 때마다 반드시 남길 사실

- **매번 한 묶음의 실제 작업 실행/조사/검증/차단이 끝나면, 다음 대화로 넘어가기 전에 지정 진행 기록을 같은 응답 주기 안에서 갱신한다.** 변경 없이 조회했거나 실패·중단·대기인 경우도 해당 단계의 상태와 최초/최종 관측 증거, 재조회 조건을 누락하지 않는다. 동일한 기존 증거만 재확인한 반복 조회는 신규 완료로 계산하지 않는다.
- 필수 기록 필드: **실행 시각(KST), 단계 번호와 소유자, 이번 목표/범위, 실제 수행(변경 파일·소스/테스트/PR/Issue/Run), 시작 기준 SHA와 종료 SHA, 검증 명령/대상·PASS/FAIL·증거, 운영 PC/SQLite/D1/API/UI 적용 여부, 문제·LAST PASS/FIRST FAIL, 남은 정확한 작업, 다음 단 하나의 실행(담당·대상·입력·통과 조건), 단계별 상태·완료 번호·누적 진행률**.
- PR은 `Draft/Open/CI PASS/Merged`를 구분하고 운영은 `소스/모의시험/실PC 설치/로컬 저장/D1 게시/공개 API·화면`으로 분리한다. **PR·CI 완료 = PC/D1/Production 완료가 아니다.** 승인받지 않은 산식/TTL/샘플 간격/DB·수집 주기·배포 변경은 시도하지 않고 미완료로 분리한다.

### 3. 작업 종료 트랜잭션 (보고보다 먼저)

1. 실제 수행과 관련 테스트를 끝내고 해당 단계의 **통과 조건에 대한 증거**를 확보한다.
2. 작업 내용과 별도로 지정 진행 기록 `.md`의 **현재 인계 정본 상태표 및 최근 실행 기록**을 업데이트한다. 단계 수를 바꾸면 완료 번호를 전수 재집계하여 `완료 + 미완료 = 75`를 확인한다. 기존 과거 이력은 지우지 않고 최신/과거를 구분한다.
3. `codex/ui-improvements`에 **정확한 파일 단위**로 진행 기록을 커밋한다. 브랜치 HEAD·커밋 SHA를 확인하고 원격에서 **바로 해당 파일을 다시 읽어** 제목, 최신 단계/진행률, PR·증거, 미해결 사항, 다음 실행 내용을 검증한다.
4. **재조회 PASS 이후에만** 사용자에게 이번 결과와 **기록 반영 커밋**을 보고한다. 원장 쓰기 실패·충돌·불일치·도구 접근 차단 시 **`LEDGER_UNVERIFIED / 인계 미완료`**로 표시하며 작업 기능이 실제 수행됐더라도 전체 종료·인계 완료로 주장하지 않는다. 원장 수정이 허용된 범위라면 충돌 난 해당 파일만 새 SHA 기준으로 보존·재적용한다. 강제 push/reset/clean은 금지한다.
5. 아직 수행하지 않은 결과, 미래 예약 검증, 다른 대화의 자동 수신을 `DONE`으로 기록하지 않는다. 마지막 보고에는 **'진행 기록 원격 확인: PASS/미확정'**을 필수 기재한다.

### 4. 75단계 상태·진행률 판정

- `DONE`: 그 단계의 **계획서 완료 증거**가 실제 존재할 때만; `PARTIAL`: 코드/fixture만 있고 단계의 운영 통과조건 미충족; `READY`: 다음 실행 가능; `RUNNING`: 실제 진행 증거 확보; `STATE_UNKNOWN`: 런타임 확인 불가; `BLOCKED`: 해당 실행의 승인·권한·검증 차단; `DEFERRED`: 현재 필수 실행이 아닌 후속.
- 작업 항목의 성격이 분석·설계면 **소스·fixture·설계 증거만으로 해당 단계 DONE** 가능하나, 이를 운영 적용 DONE이라 확장하지 않는다. 개발·설치·게시 단계는 그 항목에 명시된 PC/공개 검증을 충족할 때만 DONE으로 계산한다.
- 진행률 = **서로 다른 DONE 단계 번호 개수 / 75 × 100**, 소수 첫째 자리 반올림. 부분·초안·CI 진행 중·미실행 항목은 분자 제외. 완성된 PR의 개수로 진행률을 증가시키지 않는다. **27개 D01–D27 각각의 최종 상태는 별도로** 유지한다.

## 실제 수행의 병렬화/정지 원칙

- A/B의 소스/fixture/대상별 판정 및 UI 코드 검사는 서로 독립이면 병렬 진행. Core SQLite 동일 writer, D1 publish, 공용 lease/설치는 같은 lane만 직렬화.
- 수집/계산/게시 원담당과 W06의 실제 인계·승인 근거 없이 다른 대화가 자동 업무를 받았다고 가정하지 않음. 구현·병합·운영실증의 해당 담당을 구분.
- RUNNING은 로컬 저장·원장·checkpoint 실제 전진으로 판단. 개별 최신 자료 없으면 유효 마지막 값을 유지하되 새 관측이라고 위장하지 않음.
- 75번 완료 시 **사용자에게 홈페이지 직접 확인 요청**. 그 이전에는 웹디버그나 수동 PC 작업/화면 확인을 사용자에게 요구하지 않음.
