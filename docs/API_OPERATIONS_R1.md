# ZGmini API 호출·저장 관리 기준 R1

업데이트: 공개 피드 저장형 구현은 [STORED_ONLY_R1](STORED_ONLY_R1.md)을 우선한다. 아래 초기 조사 내용 중 CNN 메모리 캐시와 market-data 직접 호출 설명은 전환 전 기록이다.

확인일: 2026-10-01. 비공개 저장소 내부 운영 문서. 산식·키 값·원자료를 포함하지 않는다.

## 적용 범위와 상태

이 문서와 `config/api-operations.json`은 현행 수집 설정을 조회하는 관리 대장이다. JSON 자체는 런타임에서 로드되지 않으며 호출 제한을 새로 강제하지 않는다. 17개는 주요 경로의 제공처 수이지 API 엔드포인트 수가 아니다. 기존/보조 엔드포인트까지 모두 저장형이라는 의미도 아니다.

- 종합지표: 5분마다 13개 작업 중 하나, 기본 한 바퀴 약 65분. 매번 17개를 모두 호출하지 않는다.
- 한국: 15분마다 수집 시도. 미공표·휴장·이미 저장된 날짜는 실제 요청 수와 저장 결과가 달라진다.
- 주기는 2026-09-30 운영 검증 기록이며 오늘 예약 관리자 상태를 다시 확인한 것은 아니다.
- 기업실적은 수집기 내부 기본 6시간 갱신 제한도 있으므로 65분마다 외부 전체 호출하는 것으로 계산하지 않는다.
- 호출 수는 페이지 수·종목 수·빈티지·재시도·backfill·수동 실행을 모두 포함한다. 288회/일은 5분 예약 횟수이지 제공처 요청 횟수가 아니다.

## 저장 위치와 처리 계약

운영 저장소는 `.openai/hosting.json`의 Cloudflare D1 바인딩 `DB`다. Windows 경로나 GitHub 파일이 운영 DB를 대체하지 않는다.

| 저장 대상 | 위치 |
|---|---|
| 공통 정규화 입력 | `market_input_batches_v1` |
| 공개 산출 점수 | `market_public_snapshots_v1` (일자 + current) |
| 실행·잠금·마지막 처리 상태 | `market_collection_jobs_v1` |
| 유동성 점수 이력 | `market_liquidity_active_history_v1` |
| 지표별 상세 저장 | JSON의 storageModules에서 테이블 정의 확인 |

공통 경로는 수집 → 정규화 입력 저장 → 저장 자료로 산출 → 산출 점수 저장 순서다. `/api/market-score`는 저장 점수만 읽는다. 같은 날짜 입력은 upsert로 대체하므로 모든 호출 응답을 영구 버전별 보관하는 구조는 아니다. 현재 공통 입력 신선도는 36시간, 공개 점수 저장시각 유효기간은 30분이며 실제 관측일의 신선도와 구분한다. 자동 삭제/보존기간은 공통 저장 모듈에 별도 지정되어 있지 않다.

## 미완료·보완 대상

- CNN: 60초 메모리 캐시이며 D1 영구 저장·독립 예약 수집 미연결.
- 제공처 공통 영구 quota counter/429 Retry-After 제어는 이 관리 대장에서 강제하지 않는다. 기존 수집기의 제한만 동작한다.
- BLS: 미등록 경로가 여러 작업에서 호출되어 25회/일 초과 위험이 있다. 전체 호출 집계 없이 안전하다고 판정하지 않는다.
- KRX/ECOS: 실제 승인 서비스·키의 한도 확인 필요.
- 신규 공통 제한 적용 시 모든 호출 경로/수동 복구 호출까지 합산하고, 저장 점수 30분 유효기간과 수집 주기를 함께 검토해야 한다.
- `app/api/market-data` 및 기타 보조 API는 별도 경로로, 이 대장이 전환 완료를 의미하지 않는다.

## 장애·재시도·보안 운영 기준

향후 공통 제어를 추가할 때 적용할 기준이며, 전 경로 구현 완료를 뜻하지 않는다.

1. 429/QUOTA_EXCEEDED는 인증 실패와 구분하고 즉시 반복하지 않는다. Retry-After 또는 다음 한도 창까지 대기한다.
2. 401/403은 원응답 분류 후 인증·권한을 확인한다. 토큰을 로그로 남기지 않는다.
3. 저장 실패를 수집·계산 완료로 보고하지 않는다. 빈 응답으로 기존 정상 값을 가짜 0으로 대체하지 않는다.
4. 재실행은 기존 checkpoint와 lease를 사용한다. 미공표 자료는 WAITING_PUBLICATION으로 구분한다.
5. 키/인증 URL/요청 헤더/원자료는 GitHub 문서에 포함하지 않는다. 공개 이용 권리를 무료 접근과 동일시하지 않는다.

## 점검 명령

```sh
node scripts/check-api-operations.mjs
```

이 명령은 항목 수·중복·수집/저장 파일 존재·D1 바인딩을 검사한다. 실제 API 호출, quota 잔여량, 운영 DB 저장 성공은 검사하지 않는다.

GitHub 등록과 운영 배포는 별개다. 이번 등록은 API 제공처·산식·화면·운영 스케줄을 변경하지 않는다.
