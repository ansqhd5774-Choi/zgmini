## 2. 사용자 최신 확정 의도 — 가장 중요한 계약

**장중 잠정치와 마감 확정치는 서로 다른 데이터 생산물이다.**

| 구분 | 장중 잠정치 | 마감 확정치 |
| --- | --- | --- |
| 목적 | 장중 시장 등락을 현재 관측 범위로 표시 | 거래일별 최종 등락 기록 |
| 공급원 | Alpaca IEX | 기존 MarketParquet |
| 주기 | 미국 정규장 15분 간격 | 완료 거래일별 확정 |
| 결과 | 시간에 따라 갱신, 미관측 종목 가능 | 기존 확정 산식·검증 규칙 적용 |
| 상호 대조 | 확정치와 일치할 의무 없음 | 잠정치로 대체하거나 수정하지 않음 |

사용자가 직접 지적한 사항:

1. **잠정치는 잠정치이다.** Alpaca 잠정치가 MarketParquet 확정치와 같아야 한다고 요구하지 말 것.
2. 확정치에 적용한 **98% 확보 기준을 잠정치의 필수 통과/발행 기준으로 복제하지 말 것.**
3. 500개 중 100개만 관측했으면 그 **100개에서** 상승·하락·보합을 계산할 수 있다. 동시에 관측 `100/500`, 미관측 `400`, 시각·출처를 명시한다.
4. 미관측 종목을 상승/하락/보합/0으로 임의 분류하거나, 관측된 일부만으로 전체 500개를 대표한다고 단정하지 않는다.
5. **정확한 잠정치 수집·계산·15분 갱신·표시**가 목적이다. 잠정치와 확정치의 방향 일치율 입증은 작업 목표가 아니다.
6. 기존 MarketParquet 확정치와 250거래일 이력, 확정치 산식·게시 경로를 변경하지 않는다.

주의: 잠정치의 '미관측'은 데이터의 현실적인 상태이고, 임의의 합격률을 새로 도입하지 않는다. 단, API 응답이 **페이지 중간에서 끊긴 경우**에는 표본이 종목명 순서로 치우칠 수 있다. 이 사실을 오류/부분 수집으로 구분 표시하되, 확정치 합격 기준을 끌어오지 않는다.

## 4. 새 대화에서 할 실제 작업

1. **원격 상태·지침 확인.** `AGENTS.md`, `docs/MARKET_BREADTH_US_R1.md`, 작업 브랜치 최신 HEAD, `main` 최신 HEAD, 실제 PC 운영 승인 버전의 차이를 확인. 기존 전용 브랜치를 그대로 사용한다.
2. **잠정치 전용 데이터 계약 확정.** 정규장 15분 주기, S&P 500 대상 명단, 장중 가격과 전일 비교 기준의 출처·조회 방법, 상승/하락/보합/미관측 분류, 시각·신선도·출처를 명세한다. 확정치 데이터 공급자/검증 수단과는 분리한다. 전일 비교 기준이 기존 저장 가격과 결합되는 경우에도 잠정치의 계산 입력인지, 확정치 대조인지 구분하고 사용자 승인 범위를 벗어나지 않는다.
3. **수집 구현.** 가용 IEX 시세를 저장하고 저장 데이터로 잠정 등락을 계산한다. 여러 종목 조회는 페이지 종결까지 처리하거나 응답이 부분 수집인 경우 명시적으로 기록한다. 불완전한 페이지를 전체 시장 자료로 가장하지 않는다.
4. **15분 운영 연결.** 기존 PC 예약 실행기·게시 경로 재사용을 우선 검토한다. 승인된 작업 외에 별도 예약 작업, Cloudflare Cron, D1 스키마, 새로운 유료 API를 만들지 않는다. 기록 시점과 장 휴일·개장 전·마감 후 처리 원칙을 분리한다.
5. **공개 표시 연결 및 검증.** 잠정치에는 `잠정` 라벨·관측/전체 수·상승/하락/보합/미관측·기준 시각을 표시한다. 확정치는 기존 데이터와 이력 그대로 보여준다. UI 변경은 `AGENTS.md`에 지정된 UI 전용 브랜치 `codex/ui-improvements` 규칙과 병합 승인 범위를 먼저 확인한다.
6. **실제 운영 판정.** 코드 테스트와 PC 설치/예약 수집/원자료 저장/게시/D1 readback/공개 화면 확인을 별도 Gate로 보고한다. 준비된 ZIP만으로 운영 완료라고 보고하지 않는다.

### 남은 필수 실행과 STOP

1. 다른 작업자 운영 파일을 수정하지 않는 독립 **US 전용 B급 PC 소스 인계 계약**을 마련한다. 현재 실제 Core Action/승인 source와 Git 후보의 정확한 경로·변경 파일 해시를 확인한다. Core task/lock을 삭제·수정하거나 다른 collector를 덮어쓰지 않는다.
2. 읽기 전용 진단과 Windows 격리 모의 설치·백업·검산·복구 확인 후, 별도 승인된 source 변경만 Core 유휴·자원 잠금 조건에 맞춰 적용한다. 일반 `pc-job`에 임의 shell/SQL을 보내거나 Controller 갱신 경로로 운영 소스를 우회하지 않는다.
3. 실제 뉴욕 장중 자연 발생 15분 슬롯의 수집/원자료 저장/로컬 계산/잠정 D1 게시·재조회, 공개 API 최신성 및 PC·모바일 비율 표시를 검증한다. 별도 스케줄러·DB 구조·MarketParquet 확정치·기존 이력은 변경하지 않는다.

이 단계에서 Runtime 실패를 확인한 것은 아니며, **미설치 운영 경로는 `AUTOMATION_BLOCKED`**다. 독립 조사와 테스트는 계속하되 B급 새 운영 변경은 해당 승인/담당 배정 없이 실행하지 않는다.
