## 5. 4단계 — 미래 월말 오표시와 실제 화면

## 6. 5단계 — 자동 갱신과 실제 종결

기존 정규 Core 실행 원장/공급자 checkpoint/Writer 게시 또는 UNCHANGED/readback을 연결해 각 그룹의 공식 주기에 맞는 갱신을 확인한다. 모든 월간·분기 지표에 같은 날짜를 요구하지 않는다. 정상 UNCHANGED와 장기 차단·호출 전 실패를 구분하고 관찰 timeout만으로 장시간 작업을 실패 처리하지 않는다.

현재 유효한 실행 근거가 있으면 다음 날·다음 발표를 새 출시 조건으로 붙이지 않는다. 새 실행이 꼭 필요한 범위만 기존 승인 경로로 확인하고 미검증을 그대로 보고한다. 새 감시 예약·중복 CMD·Controller·워크플로를 만들지 않는다.

각 수정은 정상본/설정/해당 D1 key preimage를 기존 백업·원장에 보존하고 실제 검증한다. 확정 실패는 해당 범위만 정상본으로 복귀·정상 확인 후 후보를 별도 분석한다. UNKNOWN이면 실제 결과를 읽고 무작정 재시도·원복하지 않는다. 관련 source가 바뀐 검사만 다시 수행하며 운영에 고의 실패를 주입하지 않는다.

완료는 실제 원자료 확보/정당한 미발표·결측, 기존 승인 계산 보존, 실제 저장·게시·readback·화면·자동 실행의 범위로 판정한다. 기능 정상과 합법적 자료 부족을 분리하고 예전71행을 모두 체크하기 위한 불필요한 실행을 하지 않는다.
