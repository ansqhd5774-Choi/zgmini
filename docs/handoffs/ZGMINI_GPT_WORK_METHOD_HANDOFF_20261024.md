## 2. 핵심 작업 철학 — 빠른 반복, 그러나 관측과 변경을 분리

1. **먼저 관측**: 사용자 보고, 실제 운영 사이트, GitHub 코드, 배포 기록의 불일치를 확인한다. 사이트가 어떻게 생겼는지 추정하지 않는다.
2. **변경 범위 고정**: 해당 페이지/컴포넌트/스타일만 수정한다. 데이터 산식, API, DB, 등록부, 스케줄러, DNS 등은 별도 명시적 승인 없이는 절대 수정하지 않는다.
3. **작은 수정 단위**: 원인을 분리하고 필요한 최소 변경만 한다. 리뉴얼하면서 이미 동작하는 상호작용·데이터 연결을 무너뜨리지 않는다.
4. **사용자에게 실제 화면으로 보여주기**: 개념 설명보다 시안·미리보기·PC/모바일 결과를 활용하고, 사용자의 의견을 받아 빠르게 반복한다.
5. **검증 전 ‘완료’ 금지**: 코드 반영, PR 병합, Cloudflare 배포, 공개 URL 반영은 서로 다른 상태다. 마지막 공개 검증이 빠지면 `PARTIAL` 또는 `BLOCKED`라고 보고한다.
6. **보고는 짧고 정확하게**: 승인 요청, 차단, 오류, 변경안, CMD 실행 요청이 아니면 불필요한 중간 보고를 줄인다. 다만 길어지는 작업은 현재 확인된 사실을 간결히 알려준다.

## 3. 도구를 쓰는 순서와 선택 규칙

### A. 저장소·코드

- 가능하면 GitHub 전용 연결 도구/기존 인증을 우선 사용한다. 로컬 저장소가 연결되어 있다면 작업 시작 전 `pwd`, `git status --short`, 현재 브랜치, `git rev-parse HEAD`, `git remote -v`를 읽기 전용으로 확인한다.
- `AGENTS.md` 및 관련 프로젝트 문서를 먼저 읽는다. 저장소에 있는 변경 사항은 사용자의 작업일 수 있으므로 덮어쓰지 않는다.
- 탐색은 `rg` / `rg --files`를 우선하고, 실제 셀렉터(`zg-terrain-axis`, `zg-terrain-axis-label`, `zg-terrain-axis-bands`, `zg-terrain-axis-ticks`)를 기준으로 코드의 진짜 위치를 찾는다.
- 공개 URL, main SHA, 작업 브랜치 SHA, 빌드·배포 SHA를 별도로 기록한다. 동일하다고 추정하지 않는다.
- PR이 필요한 구조라면 범위 제한 브랜치 → 테스트 → PR → 리뷰/체크 확인 → 병합 → Cloudflare 자동배포 확인 → 공개 검증 순서로 진행한다.

### B. 브라우저: 사이트의 ‘실제 모습’을 확인하는 도구

- 브라우저 전용 플러그인/스킬이 제공되면 그것을 우선 읽고 따른다. 사용할 수 없는 경우 명시적으로 허용된 클라우드 브라우저를 사용한다.
- **클라우드 브라우저와 사용자 Windows PC의 구글 크롬은 별개**다. 같은 화면·로그인·쿠키가 공유된다고 가정하지 않는다. 특정 브라우저로 열라는 지시가 있다면 그것을 따른다.
- 명시적인 사이트 작업을 위한 공개 페이지 확인에는 운영 URL을 직접 연다. 일반적인 인터넷 정보 조사와 사이트 조작을 구별한다.
- UI 상태(스크린샷/DOM/접근성 트리)를 읽고 요소의 실제 위치와 동작을 확인한다. 선택 버튼이라면 두 번 눌러 ON→OFF 복귀까지 점검한다.
- 바꾼 영역을 PC와 모바일 화면 크기로 비교한다. 좁은 화면에서 글자가 겹치거나 점·선·눈금이 잘리지 않는지 확인한다.
- 인증이 필요한 화면에서 차단되면 우회하지 않는다. 허용된 로그인 안내 절차에 따라 사용자에게 요청한다. 사용자 계정의 임의 로그인, 비밀정보 추출은 금지다.
- ‘브라우저에서 클릭할 수 있었다’는 사실이 소스 코드의 수정·배포를 의미하지 않는다. 모든 주장에 증거를 남긴다.

### C. 명령 실행: 사용자 Windows는 CMD만

- 사용자의 PC에서는 **CMD만 사용**한다. PowerShell, WSL, Ubuntu를 요구하지 않는다.
- 실행을 요청해야 한다면 `.cmd` 파일 한 개로 절차를 단순화하고, 같은 폴더에 `_RESULT.txt` 또는 `_EXECUTION_LOG.txt`가 생성되게 만든다.
- 사용자는 결과 파일을 바로 찾을 수 있어야 한다. `%TEMP%` 및 발견하기 어려운 `E:\ZGmini\data\pc-writer\` 경로에 전달용 로그를 저장하지 않는다.
- 용량이 큰 실제 원자료와 작은 사용자 전달용 로그를 분리한다. 기존 원자료를 옮기거나 삭제하지 않는다.
- 명령마다 실행 시각, 읽은 대상, SHA/경로, 성공·실패, 누락 원인, 다음 단계가 보이게 한다. 실패를 성공처럼 요약하지 않는다.

### D. 서브에이전트 활용: 독립 과제만 분리

- 다음 GPT 환경에서 다중 에이전트가 **허용되고 사용자가 요청했을 때에만** 활용한다. 이 문서가 권한을 새로 부여하는 것은 아니다.
- 예시 역할 분담:
  - 진단 담당: 코드에서 대상 페이지·셀렉터·데이터 의존성 파악(읽기 전용).
  - UI 담당: 데스크톱/모바일 시각·상호작용 결함 확인(읽기 전용 또는 별도 범위).
  - 테스트 담당: 회귀 시나리오와 테스트 결과 확인(읽기 전용).
- **동일 파일을 여러 에이전트가 동시에 수정하지 않는다.** 각 역할의 산출물이 겹치면 본 담당 GPT가 차례로 통합한다.
- 서브에이전트 보고를 그대로 사실로 채택하지 않는다. 본 담당 GPT가 주요 증거, diff, 테스트, 공개 배포 상태를 다시 확인한다.
- 작업 영역이 작거나 역할을 나눠도 이익이 없으면 단일 GPT가 직접 처리한다.

## 4. 한 번의 UI 수정에 적용할 표준 작업 루프

1. **문제 정의**: 사용자의 원문을 1~3문장으로 바꾸고 수정 대상 URL·컴포넌트·비변경 영역을 적는다.
2. **운영 상태 수집**: 공개 사이트 PC/모바일 화면, 요소 구조, 실제 UI 반응을 읽는다.
3. **소스 역추적**: 해당 셀렉터의 컴포넌트·CSS·테스트 파일을 찾고 운영과 로컬 차이를 확인한다.
4. **수정안 확정**: 수치·레이블·점·점선·색상·레이아웃을 별개로 체크한다. 디자인이 아직 미확정이면 시안을 먼저 보여준다.
5. **최소 구현**: 데이터 변경 없이 해당 UI 범위에서만 수정한다.
6. **검증**: 정적 검사 → 프로젝트 테스트 → 실제 브라우저 클릭/스크롤 → PC와 모바일 다중 너비 → 기존 페이지 회귀를 확인한다.
7. **자동배포**: 승인된 저장소 정책에 따라 PR 병합 및 Git Integration으로 배포한다. Cloudflare에서 실제 성공 여부와 SHA를 확인한다.
8. **공개 검증**: 캐시·지연 가능성을 고려해 운영 URL을 새로 열고 DOM/화면 및 클릭 동작을 확인한다.
9. **최종 보고**: 변경한 것, 변경하지 않은 것, 시험 결과, PR/SHA/배포 여부, 공개 URL, 남은 차단 요소를 간단히 명시한다.

## 5. 당장 이어서 해야 할 업무: 경제 지표 표 디자인 적용

### 대상

- 운영 URL: <https://zgmini.kr/economic-indicators/>
- 표 축 컴포넌트: `.zg-terrain-axis`
- 관련 영역: `.zg-terrain-axis-label`, `.zg-terrain-axis-plot`, `.zg-terrain-axis-bands`, `.zg-terrain-axis-ticks`

### 사용자와 대화에서 합의된 디자인 방향

1. 왼쪽 3개 열의 기존 밋밋한 `# | 지표 | 현재 안정 점수`를 더 명확한 강조형 헤더(`순위 | 경제 지표 | 안정 점수 /100` 취지)로 개선한다.
2. **헤더와 각 행의 순위·지표명·안정 점수는 가로·세로 중앙 정렬**하여 실제 컬럼 중심축이 일치하도록 한다. 긴 지표명에서 모바일 겹침을 따로 검증한다.
3. 5구간은 원래 확정 비율 **취약 25% / 주의 20% / 중립 10% / 양호 20% / 우수 25%**를 유지한다. 경계는 **0 / 25 / 45 / 55 / 75 / 100**을 유지한다.
4. 5개 구간명은 해당 색상 헤더 블록의 가운데에 넣고, 밴드 색을 표 행의 배경까지 **옅게 수직으로 연장**한다.
5. 각 행에는 **0점 시작점부터 해당 행 실제 점까지 같은 색의 가로 점선**을 복원한다. 점은 점수 위치에 오도록 한다.
6. 수치 범위를 중복해 길게 설명하지 말고, 하단 눈금 숫자만 깔끔하게 둔다.
7. 배경·모서리·폰트는 현행 ZGMINI 스타일과 조화시키며 타 페이지 디자인을 무단 변경하지 않는다.

### 중요한 현재 상태

- 이 디자인은 **이전 대화에서 SVG 시안으로 제시되고, 사용자에게 정렬 변경 방향까지 확인받은 상태**다.
- 사용자는 2026-10-24에 ‘개선하고 적용해줘’라고 요청했지만, **이 문서를 작성하는 현재 시점에는 소스 수정·PR·배포·운영 검증의 성공 증거가 없다.** 완료된 것으로 보고하지 말 것.
- 현재 새 작업공간에 ZGMINI 로컬 파일이 보이지 않았다. 저장소/연결 권한부터 확인하고 무작정 디렉터리를 새로 만들거나 다른 프로젝트를 변경하지 말 것.
- **변경 범위는 경제 지표 표의 디자인과 정렬**이다. 검색/정렬 UI, 테마 공포·탐욕 페이지, 데이터 산식·스케줄러 등 다른 기능은 건드리지 않는다.
