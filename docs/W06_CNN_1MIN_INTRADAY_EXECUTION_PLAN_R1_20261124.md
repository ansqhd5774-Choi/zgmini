## 3. 반드시 구분할 세 가지 기록

### 원본 확인 기록

HTTP 요청 결과와 실제 확인시각인 `checkedAt`을 기록한다. CNN 원본이 그대로여도 확인 자체는 정상적으로 수행될 수 있다.

### 원본 관측 이력

CNN이 제공한 원본 점수와 `observedAt`을 보존한다.

- 같은 원본을 다시 확인했다고 새 관측시각을 만들지 않는다.
- 원본 정밀도를 반올림해 저장하지 않는다.
- 같은 시각의 상충 값은 기존 정정·충돌 계약으로 처리한다.
- 늦게 도착한 자료와 현재값의 역행을 구분한다. 최신값 역행 방지를 이유로 유효한 과거 기록을 무조건 버리지 않는다.

### 차트 표시 결과

원본 관측에서 파생한 표시용 결과다.

- 화면은 소수점 첫째 자리로 표시한다.
- 인접한 동일 표시값 때문에 불필요한 변동점을 추가하지 않는다.
- 중간에 다른 값이 있었다면 이전 점수로 돌아오는 변화도 보존한다.
- 차트 필터를 적용해도 원본 관측은 삭제하지 않는다.

## 4. 실행계획 — 7단계

### 1단계. 현재 실제 수집·게시 경로 확정

필요한 범위에서 다음 경로를 대조한다.

- CNN 수집기와 피드 갱신 정책
- PC `collect-local`·quota 정책·실제 실행기
- 기존 CNN Sidecar 또는 승인된 실행 연결
- 관측 이력 모듈과 SQLite 저장 경로
- D1 게시기·관측 API·`cnn-panel.tsx`

파일의 설정값과 실제 실행 중인 설정을 구분한다. #1521에서 이미 입증된 정상 저장·게시·화면 결과는 재사용한다.

**완료 기준:** 실제 HTTP 호출부터 화면까지의 경로와 최초 미완료 지점이 특정된다.

### 2단계. CNN만 1분 확인하도록 연결

15분·5분 제한 중 실제 CNN 경로에 적용되는 부분만 수정한다. 사용하지 않는 설정까지 일괄 변경하지 않는다.

- 기존 승인 실행기가 1분 실행을 지원하면 재사용한다.
- 5분 Core의 설정값만 바꾸고 1분 실행이 된 것으로 판단하지 않는다.
- 기존 실행기로 불가능하면 필요한 실행 연결 변경을 한 가지로 특정한다. 신규 예약·서비스를 임의 추가하지 않는다.
- 동일 CNN 수집의 중첩을 방지하고, 장시간 요청 때문에 무제한 대기열을 만들지 않는다.
- 429·서버 오류·응답 지연은 적절히 대기하고 마지막 정상값을 보존한다.
- 공급자 허용 범위와 기존 유효한 이용 근거를 확인하되 같은 조사를 반복하지 않는다.

**완료 기준:** 정상 자연 실행에서 60초 기준의 실제 요청 기록을 확보하고, 다른 지표의 실행 주기·호출 정책이 유지된다. 실패로 건너뛴 주기는 별도로 표시한다.

### 3단계. 원본 저장과 변동 감지 구현

기존 저장 경로에서 원본 관측을 먼저 보존하고, 그 결과로 차트 표시 여부를 판단한다.

예시:

| 원본 점수 | 표시값 | 직전 표시값 | 처리 |
| --- | --- | --- | --- |
| 15.81 | 15.8 | 없음 | 최초 점 |
| 15.83 | 15.8 | 15.8 | 원본 보존, 중복 변동점 생략 |
| 15.87 | 15.9 | 15.8 | 새 변동점 |
| 15.81 | 15.8 | 15.9 | 복귀 변동점 |

숫자 비교와 표시 반올림은 하나의 공통 규칙을 사용한다.

**완료 기준:** 원본 정밀도·관측시각·확인시각이 보존되고, 차트에는 실제 표시값 변화가 정확히 반영된다.

### 4단계. 1D 자동 1분 집계와 선형 차트 구현

기존 `1D`를 누르면 별도의 확인 이력·1·5·10·30분 버튼 없이 **실제 CNN 원본 observedAt 기준 1분 선형 차트**를 즉시 표시한다. 기간 선택 `1D·1W·1M·3M·6M·1Y`는 그대로 유지한다.

집계 기준:

- 1분 구간을 기존 뉴욕 거래일·시간대 계약에 맞춰 나눈다.
- 각 구간의 실제 관측 중 마지막 값을 선형 차트 대표값으로 사용한다.
- 구간 대표시각과 실제 마지막 관측시각을 구분한다.
- 원본 관측 전체로 집계한 뒤 표시 중복을 정리한다.
- 같은 값이 다른 구간에서 실제 관측됐다면 원본·집계 기록을 유지한다.
- 관측 없는 구간을 이전 값 복사로 채우지 않는다.
- 결측을 숨기는 선 연결이나 가짜 연속 관측을 만들지 않는다.
- 현재 진행 중인 구간은 마감된 구간과 구분한다.

OHLC 데이터나 캔들 계산을 새로 만들지 않는다.

**완료 기준:** `1D` 선택 즉시 1분 집계가 나타나고 보조 선택 버튼 없이 기존 선형 스타일·툴팁이 유지된다. 확인 이력은 원자료로만 보존하며 1D 원본 분봉으로 혼합하지 않는다.

### 5단계. D1·API·화면 자동 갱신 연결

기존 경로를 유지한다.

`CNN → SQLite → 관측 이력 → D1 → 저장 전용 API → 화면`

- 변경된 관측이 기존 게시 경로로 전달되는지 확인한다.
- 게시 결과가 불명확하면 D1을 먼저 재조회한다.
- API 캐시 때문에 1분 화면 갱신이 오래된 값을 반복하지 않는지 확인한다.
- 현재 점수뿐 아니라 관측 아카이브도 화면에서 주기적으로 재조회한다.
- 기간 변경과 자동 조회가 겹칠 때 오래된 응답이 새 결과를 덮지 않게 한다.
- 화면 조회에서 CNN 직접 호출이나 수집 작업을 발생시키지 않는다.
- 실패 시 마지막 정상 결과와 지연 상태를 유지한다.

**완료 기준:** 새 공개 관측이 페이지 새로고침 없이 카드와 차트에 일관되게 반영된다.

### 6단계. 집중 회귀시험과 필요한 운영 적용

필수 시험:

- 원본·표시값 동일 반복
- 원본만 변경되고 표시값은 동일
- 표시값 상승·하락·이전 값 복귀
- 중복 시각·상충 값·늦게 도착한 관측
- 요청 실패·429·복구·실행 중첩
- 1분 집계·빈 구간·미완료 구간
- 뉴욕 날짜 경계·서머타임·휴장일
- 기존 여섯 기간과 일별 이력 보존
- API 자동 조회와 응답 순서 역전

변경한 범위만 시험하고 동일 소스의 유효한 기존 검증은 재사용한다.

운영 적용이 필요하면 기존 정규 절차로 수행한다. 공통 Controller 장애는 해당 담당자에게 정확히 인계하고, 독립적인 소스·API·화면 작업은 계속한다.

**완료 기준:** 관련 시험 통과와 필요한 실제 설치·배포가 각각 확인된다.

### 7단계. 실제 관측으로 종단 확인 및 종결

자연 실행에서 다음을 확인한다.

- 최초·마지막 확인시각과 요청 간격
- 서로 다른 표시 점수의 실제 관측
- SQLite 원본과 공개 관측의 대응
- D1 readback·API·화면 일치
- PC 1440px·모바일 390px
- 1D 자동 1분 집계·툴팁·터치 및 보조 간격 버튼 미노출
- 기존 1D·1W·1M·3M·6M·1Y 보존

CNN 점수가 변하지 않았다면 수집·동일값 처리 검증은 완료할 수 있다. **실제 변동 전파만 검증 대기로 남긴다.** 변화를 만들기 위해 가짜 점수나 불필요한 추가 호출을 사용하지 않는다.

**완료 기준:** 실제 CNN 표시값 변화가 저장·게시·API·화면까지 전달되고, 1D의 1분 선형 차트가 실관측 자료로 작동한다.

## 7. 2026-11-27 사용자 확정 변경 — 1D 고정 1분 차트

이전 R1 1·5·10·30분 별도 선택안은 사용자의 명시 지시로 폐기한다. 기존 확인 이력은 데이터 무결성을 위해 저장 유지하되 `1D` 차트 입력에 섞지 않는다. `1D`는 CNN 원본 실제 관측시각의 1분 구간 마지막 점만 직접 표시하고 결측 구간을 채우지 않는다. 다른 1W~1Y 화면과 PC 수집·SQLite/D1 게시·공급처 계약은 유지한다. 소스 구현 PR #1707은 CI·병합·실배포와 별도 상태로 추적한다.

## 8. 2026-11-27 기간별 관측 시계열 밀도 확정

사용자는 Investing.com의 금융 차트처럼 1W=7점, 1M=30점으로 제한하지 말고 각 선택 기간에 여러 실제 관측점이 나타나도록 명시했다. 기존 1D 고정 1분봉·선형 차트·기간 버튼 6개·스타일과 간결한 툴팁은 보존한다. 표시 간격은 **1D=1분, 1W=30분, 1M=5시간, 3M·6M·1Y=뉴욕 관측일 단위**다. 주·월 단위의 관측점 수를 달력 일수로 제한하지 않으며, 각 시간 구간에는 보존된 CNN 원본 observedAt의 마지막 실제 관측값만 선택한다. 장중 원본이 없는 날짜는 기존 CNN 일별 이력을 표시하고, 일별·장중 중복 일자를 제거하되 뉴욕 날짜/UTC 날짜 차이로 다른 실제 일자를 지우지 않는다. PC checkedAt 확인 로그는 원장에 보존하되 차트 원본 데이터로 사용하지 않는다. 휴장·원본 미변동·결측 구간의 가짜 봉·숫자를 생성하지 않는다. 화면에 새 버튼·별도 범례·설명 문구·색상·점 장식을 추가하지 않는다.

본체의 기간별 표시 소스 [PR #1716](https://github.com/ansqhd5774-Choi/zgmini/pull/1716)은 사용자 승인 범위로, PC 수집 주기·SQLite/D1 계약·API 저장원본·공급자 호출·Cron·DNS를 변경하지 않는다. 현재 실제 저장된 분단위 원본 수가 적다면 1W/1M에서도 7개·30개 이상의 선이 보장되지 않는다. 장중 변동이 나올 때 실제 sourceObservedAt→저장→공개 데이터→화면 연동 증거로 종단 완료를 별도 판정한다. 기존 1M 이상 공개 API의 표본 추출 정책은 변경하지 않았으며 그 범위의 정확한 5시간 종가를 샘플 밖 원본까지 입증한 것으로 확대하지 않는다.
