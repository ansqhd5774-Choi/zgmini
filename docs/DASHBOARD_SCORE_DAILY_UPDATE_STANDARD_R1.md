# ZGMINI 대시보드 최신자료 반영·일별 점수 확정 공통 기준 R1

- 확정일: 2026-11-10 (KST)
- 승인 범위: **공통 목표·작업 기준을 전용 브랜치에 기록**. 구현·운영 적용은 별도 단계.
- 적용 대상: 대시보드의 미국/한국 공포탐욕, 미국/한국 등락, 종합점수, 위험 8, 경제 12, 섹터 11, 테마 카탈로그 30 및 향후 승인되는 점수형 콘텐츠.
- 우선 원칙: **최신 유효 입력의 신속한 반영 + 날짜별 실제 계산 점수의 신뢰성 있는 보존**.
- 보존 대상: 기존 승인 산식·가중치·정규화·READY/잠정/확정 기준·공급자 권한·원자료·저장 이력·TTL·현재 Task/Runner/Writer. 이 문서만으로 운영 설정을 변경하지 않는다.

## 1. 세 가지 시각과 두 개의 점수는 구별한다

1. **입력 주기:** 구성 지표 자체의 발표/관측 주기(일·주·월·분기·비정기)이며 전체 점수의 의무 갱신 주기가 아니다.
2. **최신 점수:** 저장된 최신 유효 관측자료로 승인 산식을 재계산해 게시한 현재값. 승인된 신규 입력이 반영되면 당일에도 여러 번 바뀔 수 있다.
3. **일별 점수:** 해당 날짜의 실제 계산·게시 기록을 근거로 남긴 일별 스냅샷. 단순 달력 날짜의 생성이나 과거 이월만으로 신규 관측·확정이라고 주장하지 않는다.
4. **일별 확정:** 그날의 최종 스냅샷과 사용 입력 버전·기준시각을 기록하는 별도 행위. 당일 잠정/현재값과 명확히 구분한다.
5. **원지표 확정:** 월간·분기 지표의 공식 확정/개정은 일별 점수 확정과 별개다. 일별 점수를 확정했다고 그날 모든 구성 지표가 최종 확정된 것은 아니다.

## 2. 신규 지표 반영 기준

1. 승인된 공급자 수집·수동 승인 입력으로 **새로운 유효 자료가 PC 로컬 원장에 저장**되면, 기존 공통 Writer/Controller가 입력 checkpoint 또는 sourceVersion 변화를 인식해 **영향받는 산식을 가능한 다음 승인 실행 경로에서 재계산하고 게시**하도록 한다.
2. 변경된 점수가 유효하고 게시 권한·lease·검증 조건을 충족하면 **해당 날짜에 현재점수와 화면을 갱신**한다. 월간·분기 입력이 있다는 이유만으로 일괄 월말/분기말까지 보류하지 않는다.
3. 아직 새로 발표되지 않은 지표는 **해당 산식이 허용하는 마지막 유효 관측값**을 사용하며, 이월 사실과 원관측일을 추적한다. 결측/만료/불완전 자료를 숫자로 대체하지 않는다.
4. **기존 승인 산식의 전체 READY, 공통 관측월, 완성 분기, 잠정/확정 분리 조건은 그대로 유지**한다. 이 문서는 필수 입력 누락을 무시하고 점수를 만들어내라는 뜻이 아니다.
5. 원자료 저장 자체가 점수 공개 완료를 의미하지 않는다. **수집·저장 → 저장 자료로 계산 → 로컬 저장 → 승인 게시 → D1 재조회 → 공개 API/UI**의 성공을 별도 기록한다.
6. 방문자 GET은 저장된 공개 결과만 읽으며 공급자 호출·무거운 계산을 수행하지 않는다. HTTP 60초 캐시와 화면 조회 주기는 데이터 발표·계산·확정 주기와 분리한다.
7. 기존 정상 PC 실행기를 재사용한다. **신규 예약·중복 Cron·기능별 새 CMD·임의 원격 계산을 만들지 않는다.** 특히 대기 중인 장애를 이유로 일괄 추가 예약으로 해결하지 않는다.

## 3. 일별 기록과 이력 보존 기준

1. 차트의 일자 표시 기준과 시간대는 명시적으로 일관되게 관리한다. 기본 사용자 표시 날짜는 **Asia/Seoul(KST)**, 원천 관측일은 공급자 고유 기준·시간대를 별도 보존한다. US/KR 시장별 거래일 경계 및 일별 확정 cut-off는 구체 설계 단계에서 승인받는다. 현재 UTC 저장 키를 문서만으로 바꾸지 않는다.
2. 매일 유효한 현재 점수의 일별 스냅샷을 제공하는 것을 목표로 한다. 해당 날짜에 신규 원자료가 없더라도 전일 유효값을 이월할 수 있으나 **새 공식 관측이 발생한 것으로 위장하지 않는다**.
3. 당일 여러 번 재계산되면 **계산시각별 기록과 일별 최종 스냅샷을 구분**한다. 사용자에게는 현재/잠정값과 날짜별 확정값을 혼동 없이 제공한다.
4. 한 번 기록된 일별 당시 점수를 **최신 vintage 자료로 소급 재구성해 조용히 덮어쓰지 않는다**. 공식 정정 또는 산식 개정 시 원본·정정본·revision·supersedes·effectiveAt을 추적하고, 기존 방법론 이력은 보존한다.
5. 과거점에 당시 저장된 실제 계산값이 없는 경우 **현재 자료 기반 재구성/이월 점**이라고 식별하며, 확정 관측치와 같은 선·날짜·표식으로 오인하게 하지 않는다.
6. 점수 카드·차트 마지막 점·이전 대비 변화량은 사용한 **원관측일, 계산일, 게시일, 확정 상태**를 구분할 수 있어야 한다. 현재점수와 과거 차트 마지막 값이 다른 경우 날짜 차이를 알 수 있어야 한다.
7. 0, null, missing, stale, provisional, confirmed, carried-forward를 구별한다. 최근 결과가 없으면 마지막 유효 결과를 보존하되 **최신·확정으로 표시하지 않는다**.

## 4. 공통 데이터 계보와 허용 기록

- 원자료: provider, seriesId, observationDate, releasedAt/availableAt, collectedAt, sourceStoredAt, sourceVersion, status.
- 계산: scoreId, formulaVersion, inputCheckpoint/signature, calculatedAt, asOfDate, scoreRaw, displayTransformation(있는 경우), completeness, provisional/confirmed.
- 게시: localResultVersion, publishedAt, D1ReadbackAt, publicSourceVersion, publicStatus.
- 일별 이력: displayDate, marketTimezone, snapshotCutoffAt, finality, carriedForward, inputCheckpoint, calculatedAt, publishedAt, revision.
- 산식·키·원자료 전체를 공개 D1에 복제하지 않는다. 기존 저장 계약 내에서 필요한 메타데이터만 후속 설계 후 승인 범위로 반영한다.

## 5. 2026-11-10 현행 상태와 해결 과제

이번 27개 영역 + 섹터 11 + 테마 30 전수조사에서 확인된 현재 소스/화면 현황이다. **아래는 구현 완료 판정이 아닌 기준을 세운 근거**다.

- 종합점수: 12영역 최신 유효값을 혼합. 과거 일별 저장점과 현재 자료 재구성값 혼재, 같은 UTC 날짜 snapshot UPDATE 가능. 1D 실제 계산 archive, 1W~3M 혼합, 6M~1Y 저장+재구성 혼합. 과거 점의 당시 확정성이 모두 증명되지는 않음.
- 경제12: 현재점수와 차트 anchor가 다를 수 있음. 고용 카드 약 42.71 vs 차트 마지막 약 59.10, 자금흐름 시계열 최종 2026-03-01.
- 위험8: 일부는 공통 완성월/분기 점수만 확정, 일부는 새 관측을 섞은 잠정 점수를 우선 표시. 인플레이션 위험 차트의 현재월 미래 월말 label은 실제 확정일로 오인하면 안 됨.
- 섹터11: 날짜별 확정 11개 공개. 동일 확정 거래일의 공급자 정정 시 SAME_DATE_SCORE_DRIFT 거부 경로를 별도로 개선·검증할 필요.
- 테마30: 카탈로그 30, 운영 등록부 10, 공개 점수 0 (STORED_DATA_STALE). 데이터 부재를 이 기준 적용 완료로 세지 않음.
- 실제 발표일 → PC 저장 → 계산 → D1 게시 → 화면 반영 지연시간은 **운영 원장 인과 대조가 미완료**. 소스만으로 당일 반영 SLA를 보장하지 않는다.

## 6. 실행 순서와 완료 조건 (예약 추가 금지)

1. **계약 정합성:** 현재 소스·배포·PC 승인 source를 구분하고 영역별 입력 발표주기, 기존 산식 필수조건, 현재/일별/확정 상태를 표준 매핑한다. 기존 승인 조건 변경 0건.
2. **계보·이력 보존:** 기존 Writer·로컬 스냅샷 구조에 새 입력 감지와 실제 계산 기록 보존을 설계·구현한다. 과거 기록 무음 덮어쓰기 금지, 동일일 정정은 revision으로 추적. 저장 계약 변경은 사전 승인.
3. **반영 연결:** 정상 승인 수집 성공 시 기존 계산·게시 lane을 사용해 영향받은 점수를 갱신한다. 새 예약·공유 쓰기 중복 생성 금지. 실패 시 마지막 유효값과 정확한 지연 상태 보존.
4. **표시 일치:** 최신/잠정 점수, 일별 확정 이력, 재구성 점을 혼동 없게 표시한다. 카드·차트·상세페이지·기간별 마지막 점의 날짜·단위 회귀 검증.
5. **실제 검증:** 고유 원자료 입력 1개에 대해 관측일→저장시각→계산시각→D1 readback→API/UI 시각을 동일 checkpoint로 추적. 일·월·분기 혼합, 당일 다회 변경, 무변경 이월, 지연, 정정, 부분 결측, KST/US 거래일 경계 시뮬레이션. 새 점수와 과거 기록 모두 보존될 때만 완료.

## 7. 범위 제한과 진척 관리

- 이 문서 작성 자체는 **정책 기록 완료**이며 위 1~5 실행 단계의 구현·PC 설치·Production 게시를 뜻하지 않는다.
- 본 문서 승인으로 과거 점수 이력 재작성, 기존 산식·가중치 변경, 운영 수집 주기/예약/TTL/DB 경로 수정, 자동 배포가 승인된 것은 아니다.
- 후속 작업률은 1~5의 실제 증거 기준으로 별도 측정한다. 실증 없이 100% 완료를 선언하지 않는다.
