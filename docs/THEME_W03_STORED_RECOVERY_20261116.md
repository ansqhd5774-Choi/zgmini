## 권리 판단과 실제 게시 경계

- [권리 정본](API_SOURCE_RIGHTS_REGISTRY.md)의 공급자별 결론을 따른다. MarketParquet 무료 파일의 공개 파생권은 공급자 직접 거절이다. GMH는 개별 회신이 없지만 공식 약관 §5의 조건부 파생 배포 조항을 확인했다. 어느 쪽도 다른 공급자의 권리를 대신하지 않는다.
- 설치된 `r171-core.mjs`의 과거 무료 가이드 형태 검사만으로 MarketParquet 공개 권리를 인정하면 안 된다. `r179-publish-core.mjs`를 그대로 재실행해 이 오래된 검사를 통과시키지 않는다.
- 원래 저장물의 비공개·권리 플래그를 소급 수정하지 않았다. 이번 검산 결과도 `publicationAuthorized=false`, `productionVerified=false`다.

## 아직 완료되지 않은 운영 단계

- 이번 결과는 저장된 실제 데이터의 비공개 재계산이다. 운영 R178의 전체 252개 이력 저장, R179/R183 게시, D1 CAS/readback, 공개 10개 전체 갱신 또는 자연 예약 성공을 뜻하지 않는다.
- 다음 필수 단계는 기존 기준 이력의 계보와 현재 게시 경로를 연결하고, 공급자별 실제 입력 범위에 맞는 권리 검증 및 Reader 계층 비교를 적용하는 것이다. 일반화된 공개 승인 플래그나 허위 권리 객체를 넣지 않는다.
- 기존 R179의 전체 composite API 응답과 단일 rolling record의 비교는 계층이 다르다. 정확한 모델·테마 ID·관측일·값·출처를 비교해야 하며 HTTP 200 또는 stale 결과만으로 성공 처리하지 않는다.
- 공통 등록 목록 전체를 기준으로 후속 결과를 확인한다. 이번 7개 산식 검산을 기존 공개 10개 전체 또는 신규 163개 완료로 확대하지 않는다. 유효한 검산은 변경이 없는 한 반복하지 않는다.
