# 공급충격 R10 공급자 점검 대응

- 실제 2026-10-21T20:46Z FRED HTTP 성공 응답의 본문은 CSV가 아닌 `Site Maintenance` HTML이었다.
- 공급자 점검·HTTP 오류·형식 오류를 구분한다. 공개 상태에는 허용된 원인 코드만 전달하며 원문·URL·임의 에러 메시지는 노출하지 않는다.
- FRED CSV는 요청 시계열과 헤더·날짜·순서·값을 검증한다. 결측과 0을 구분한다.
- 정상 원본과 파싱 파일은 검증 후 임시 파일을 통해 교체한다. 잘못된 응답은 기존 정상 파일을 덮어쓰지 않는다. 통합 inputs.json은 모든 필수 원천 및 이력 검증 후에만 교체한다.
- 기존 성공 후 24시간 캐시, 실패 후 6시간 재시도 간격을 유지한다. 대기 중 checkedAt과 파일을 갱신하거나 성공으로 표시하지 않는다. 즉시 반복 요청·새 스케줄러 없음.
- 다음 정규 실행이 재시도 시각 이후일 때 원천별 1회 요청한다. 점검 종료나 수집 성공을 가정하지 않는다.
- 기존 원자료·산식·5영역 가중치·관측 이력·유효기간은 유지한다. 저장된 값의 날짜를 최신으로 꾸미거나 임의 대체하지 않는다.
- 배포와 PC 운영 적용, 실제 원천 재수집·게시 검증은 구분해 기록한다.
