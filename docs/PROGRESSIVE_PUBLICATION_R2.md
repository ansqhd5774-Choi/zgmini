# 저장 입력 순차 게시 R2

## 실행 순서

Core 기본 수집 → 유효한 저장 점수 조기 계산·게시 → 공급충격/Alpaca/섹터 보조 수집·계산 → 변경된 입력이 있으면 최종 계산·게시.

조기 게시도 기존 run-local 게시기를 사용하며 `--collection-degraded` 검사를 항상 적용한다. 서로 다른 12개 READY 지수와 READY 종합 점수 검증을 통과해야 한다. 산식, 고정 가중치, coverage, TTL, source 승인, lease, 세대 비교, read-back 계약을 유지한다.

## 중복 방지

조기 게시가 성공한 후 보조 작업 전후의 실제 공개 feed 출력 행, `supply-r10/inputs.json`, Alpaca 증분 수집 완료 체크포인트를 읽기 전용으로 해시 비교한다. 변경이 없으면 최종 계산·게시를 생략한다. 체크포인트를 읽지 못하거나 조기 게시가 실패하면 원래 최종 게시 경로를 수행한다. 게시 오류는 기존 recovery가 원격 read-back을 먼저 확인한다.

Alpaca 보조 수집의 예외는 상태로 기록하고 유효한 저장 자료 게시를 막지 않는다. 새 API 호출·재시도·타이머는 추가하지 않는다. 기존 보조 수집의 호출 예산과 순서는 유지한다.

## 범위

- Core의 전체 보조 수집 종료를 기다리지 않고 기본 수집으로 갱신된 저장 점수를 먼저 제공한다.
- Korea 및 게시 요청이 없는 실행은 기존 순서를 유지한다.
- 새 자료가 없는 점수를 새 잠정 관측값으로 만들지 않는다.
- 기본 collect-local 프로세스 내부의 개별 요청 도중 게시, 미발표 월·분기 입력의 nowcast, 입력 coverage 완화는 이번 변경에 포함되지 않는다.
- PC 적용은 기존 승인 SHA를 기준으로 local-cycle과 새 모듈만 선택 반영한다. GitHub main 배포와 PC 승인 실행 SHA는 구분한다.
