1. **기존 7개는 운영 기준선이다.** `worker/theme-etf-only-public.mjs`의 `THEME_ETF_ONLY_PAIRS`, `THEME_ETF_ONLY_PUBLIC_KEY`, `THEME_ETF_ONLY_PUBLIC_VERSION`, `THEME_ETF_ONLY_METHOD`, 기존 DB 테이블·키와 공개 API의 현재 응답 계약을 변경하지 않는다.
2. 기존 7개의 구성 ETF·순서, 40/20/40 요인 가중치, ETF 50/50 비중, 252거래일 확정 점수, 관측일, 잠정 최대 2일, 공개 필드·값·캐시·오류 시 동작을 보존한다. 신규 테마 때문에 기존 점수를 재산출하거나 기존 데이터 시계열을 보정하지 않는다.
3. `worker/theme-etf-rolling-public.mjs`의 검증 실패 시 기존 시드로 돌아가는 방식과 `worker/theme-ai-semiconductor-optional.mjs`의 선택적 추가 동작도 유지한다. 최신 원격 `main`에 추가된 **`worker/theme-biotech-optional.mjs`의 선택적 바이오·신약 확장**도 동일하게 보호한다. 구형/신형 승인 분기나 표시명을 임의로 교체하지 않는다.
4. 신규 ETF·공급원·라이선스 증빙의 누락이나 오류는 **해당 신규 테마에만** 적용한다. 기존 7개 API가 일괄 `503`으로 바뀌거나 기존 테마 및 이미 통과한 기존 선택적 확장이 누락되면 즉시 실패 판정이다.
5. 기존의 공개 권한이 충분히 입증됐다고 간주하지 않는다. 기존 7개의 공급원·계정 조건에 대한 권리 점검은 별도의 읽기 전용 감사로 수행한다. 증거 없이 과거 승인 플래그를 조작하거나 운영을 자동 중단하지 않는다. 실제 위반이 입증되면 별도 승인·시정 절차로 처리한다.

**4단계 준비 상태를 분리한다:**

1. `researchReady`: 테마 식별과 ETF 후보 목록만 유효하면 바로 조사 가능. ETF 비중·산식·과거 가격·공급원 권리·검증 자료가 없어도 중단하지 않는다. 다만 공급원 약관을 위반하는 자료 수집을 허가하는 상태는 아니다.
2. `calculationReady`: ETF 비중 합계, 벤치마크, 산식·가격처리 버전이 확정되어야 계산 설계가 유효하다. 이 상태에서도 권리 미확인으로 비공개 산식 작업을 차단하지 않는다.
3. `chartReady`: 실제 252개 거래일 관측 슬롯과 실점수/사유 있는 결측이 유효하면 Shadow 차트 검증 가능. 공개 권한 미확인과 독립적이다.
4. `publicationReady`: 현재 점수·권리 근거·시세 검증·개별 공개 승인 등 별도 조건이 충족된 경우에만 **사전 심사** 통과. **이 판정만으로 실제 공개하거나 GitHub main을 변경하지 않는다.**

## 3. 신규 테마별 독립 검증

- **구성:** `themeId`, 표시명, `etfs[]`, 각 ETF 가중치(합계 1), 벤치마크, 산식 버전, 가격 처리 방식을 선언한다. ETF 한 종목만 선정될 수 있고(가중치 1), ETF가 두 종목이라는 가정은 V1에만 적용한다. 구성 변경은 명시적 새 버전으로 관리한다.
- **산식:** 기존 40/20/40의 각 요인과 SPY 비교 개념을 유지할 때도 신규 테마의 단일 ETF 통합 규칙을 명시한다. 기존 7개 산식의 내부 가중치를 자동으로 재적용·변경하지 않는다. 추가 산식은 별도 승인 전까지 Shadow다.
- **기간:** 표시 창은 252거래일이다. `history` 각 날짜를 정렬·고유화하고 실제 관측치만 연결한다. 순위 산식에 필요한 과거 기간이 부족하면 해당 날짜 `score: null`, 사유 `INSUFFICIENT_LOOKBACK`을 허용한다. 원시 가격이나 날짜가 진짜 누락된 경우 `SOURCE_GAP` 등 별도 상태로 구분하며 채우지 않는다. 최신 점수가 계산 가능하다고 해서 과거의 92개 미성숙 구간을 가짜 점수로 채우지 않는다.
- **권리:** 공급원별로 사용한 데이터셋, 조회 모드(비로그인·무료 계정 등), 이용약관 URL·적용일·검토일, 보관·상업적 파생 배포·원시 재배포 허용 범위 및 확인 근거를 보관한다. `ALLOWED` 값 하나만으로는 검증하지 않고, 해당 조회 방식에 적용되는 검토자·증빙·결론을 별도로 기록한다.
- **미확인 권리의 처리:** 모호한 약관은 `UNKNOWN`으로 남기되 조사·산식·비공개 Shadow는 계속한다. 공개하려면 공급원·조회 방식에 대한 해석 근거, 이용자에게 원자료 미노출, 운영자의 명시적 위험 수용 기록·한계 공개를 별도로 심사한다. 위험 수용은 **해당 테마·ETF 구성/비중·산식 버전·가격 처리 버전·공급원·데이터셋·계정 방식·약관 증빙 식별자·가격 조정 방식**에만 유효하며 이 계약의 실질 변경 시 재승인한다. 단순히 일일 시세 검증 시각·표본 수나 약관 재확인 날짜만 갱신된 것은 과거 승인을 무효화하지 않는다. 다만 현재 데이터의 신선도·품질 검사는 매 실행 계속 수행한다. **위험 수용은 `독립적 라이선스 검증 완료`로 둔갑하지 않는다.** 이미 명시적으로 파생 배포나 저장을 금지한 공급원은 위험 수용으로 우회할 수 없다.
- **공개 승인:** 신규 테마의 권리·가격 검증은 개별 테마에만 적용하며, 미승인 기록은 신규 공개를 보류할 뿐 기존 테마에 영향을 주지 않는다. 특정 공급원 하나의 계정 조건을 모든 ETF에 공통 적용하지 않는다. 신규 공개에는 `DERIVED_SCORE_ONLY`가 필요하고 원시 봉 데이터는 배포하지 않는다.
- **가격:** 시세 데이터의 시점·시간대·정규장 종가 대비 오차·분할/배당 조정 여부를 표기한다. 원시 1시간봉과 수정종가의 차이를 감추거나 두 소스를 같은 것으로 취급하지 않는다.

## 4. 배포 전 호환성 합격조건

**기존 검증 결과 승계 원칙:** 이전에 통과한 ETF 목록·비중·산식 버전·공급원/계정 방식·약관 증빙 식별자·가격 처리 계약과 운영 승인 기록은 신규 테마 작업의 기준선이다. 신규 후보의 단순 결측·ETF 개수·가격 검증 일자·공급원 검토 상태가 기존 승인 사항을 소급 무효화하지 않는다. 변경된 계약 및 실제 영향을 받는 경로만 재검증하고, 영향을 받지 않는 운영 결과의 전체 재조사를 반복하지 않는다. 명시적 금지나 새로운 위반 사실이 확인되면 해당 범위의 별도 시정 판단을 수행한다.

1. V1 테스트 `theme-etf-only-public`, `theme-etf-rolling-r178`, `theme-etf-provisional-r158`, `theme-etf-provisional-score-r158`, `theme-ai-semiconductor-optional-r189`, 그리고 최신 main의 `theme-biotech-optional-r1` 전부 PASS. 정책 전용 테스트 `theme-etf-extension-policy-r1`도 PASS.
2. **고정 과거 스냅샷으로 새 기능 전후 비교:** 기존 7개×252일의 날짜·점수·ETF·테마 순서 및 `observationDate`, `phase`, 잠정 포인트는 동일해야 한다. 소수점 반올림이나 결측 생성도 허용하지 않는다.
3. 신규 V2 레코드가 `없음/오류/만료/권한 불명/가격 불일치/DB 조회 실패`인 6개 실패 시나리오 각각에서 V1의 HTTP 상태, 7개 시계열, 기존 선택적 AI·바이오·신약 확장이 그대로여야 한다. 신규 V2 Shadow는 V1 reader에서 호출되지 않으므로 최초 단계에서 운영 결합이 없다.
4. 기존 공개 API 경로, DB 키, 컴포넌트 렌더링, PC·모바일 1년 차트 및 잠정 점선 상태의 유지 여부를 확인한다.
5. 신규 QTUM 단일 ETF의 252개 표시 날짜 중 미성숙 92개는 `null`, 산출 가능 160개는 실제 계산 점수로 유지하는 R9 사례를 회귀 기준에 포함한다(해당 수치는 관측 자료 조건에 따른 테스트 사례이며 모든 신규 ETF에 고정하지 않는다).
6. 운영 SHA·배포 SHA·테스트 SHA, 공개 API 샘플 및 결측 사유를 기록하고, 별도 사용자 승인 없이 PR 병합·공개 전환·자동배포를 진행하지 않는다.

## 5. R1 정책 코드의 안전 범위

- 신규 `assessThemeEtfExtension`은 순수 함수다. `researchReady/calculationReady/chartReady/publicationReady`와 정확한 보류 사유를 반환할 뿐 DB·네트워크·API·브라우저·기존 7개 모듈에 접근하지 않는다.
- 신규 모듈에 **7개 테마의 목록/순서, ETF 2개 고정, 50:50 고정, GetMarketHistory/MarketParquet 이름 고정이 없다.** ETF 하나·둘·셋, 92개 초기 `null`, 공급원 다양성을 각각 검증한다.
- 라이선스 `UNKNOWN`과 제한된 가격 검증은 기존 바이오테크 사례처럼 위험 수용의 근거와 상태를 구분한다. 단순 불리언 하나만으로 독립적 확인을 주장하지 않는다.
- 2026-10-23 최신 원격 `main` SHA `bc4bda81b2efe1b473b9e5defa650c2924e4cc3a` 추출본에 정책 모듈을 독립 반영하여 기존 7개 공개 Reader·R178 롤링·R158 잠정/잠정점수·AI·바이오·게시 회복 및 새 정책 테스트 **8개 파일 전부 PASS**했다. QTUM R9 산식 패리티는 별도 로컬 테스트 PASS다. 실제 Production API 비교·배포는 **미실시**다.

## 6. 변경 불가 범위

본 기준 수립만으로 기존 V1 코드를 일반화하거나 V1 권리 검증 조건을 제거하지 않는다. 기존 점수·가중치·DB·공급원·스케줄러·DNS·현재 배포 환경을 수정하지 않는다. 신규 범용 검증기는 **기존과 물리적으로 독립된 Shadow**에서 먼저 검증한다.
