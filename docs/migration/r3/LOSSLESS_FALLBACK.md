# Lossless fallback — plan only

This is conditional, not an executable migration approval. No new DB, export/import, writer freeze or DNS change performed.

1. Obtain official source-account DB identity and export entitlement. Same-account direct binding requires authoritative ID match and permission; current evidence cannot prove it. For export use Cloudflare authorized SQL export (wrangler d1 export SOURCE --remote --output snapshot.sql) or official equivalent Sites facility. Generic support: https://developers.cloudflare.com/d1/best-practices/import-export-data/ . Do not use a guessed source name or token-bearing URL. Exported SQL is private operational data; keep outside Git and hash manifest only.
2. Inventory live sqlite_master table/index/trigger/view DDL, including runtime-created tables, exact SELECT COUNT(*) per table, PRAGMA table_info/foreign_key_list/index_list using an authorized read-only facility; DB byte size and checkpoint timestamps. Current table viewer names/48 column sets are evidence but insufficient DDL or full counts. Inspect sqlite_sequence/system migration metadata as supported. Compare against all create-table statements in preserved source; do not bootstrap from db/schema.ts alone (it contains favorites only).
3. Export format: consistent SQL DDL + data + indexes/triggers, exact text/JSON/compressed blobs, primary IDs and opaque user_id unchanged. Record snapshot time and content hash. Validate row counts and per-table PK/content hashes from actual source snapshot. Page reader is NOT a consistent full export and cannot prove completeness or deletes while writer active.
4. Following separate approval, create destination only after size/Free single-DB capacity checked. Apply source tables preserving constraints; import parents before children by actual FK graph; preserve explicit IDs/autoincrement state. Apply indexes after rows when export ordering permits; triggers after rows to avoid replay side effects. Use D1-supported deferred FK mechanism for cycles, not an assumed effective foreign_keys OFF switch. Validate FK checks, unique indexes, table counts/content hashes and stored-score/checkpoint parity. Do not run application lazy-create or score recomputation as a substitute for migration.
5. Final delta: no reliable append-only CDC/delete journal is proven. Therefore updated_at-only delta cannot guarantee zero loss. Use rehearsed full final consistent snapshot under a brief, explicitly approved writer freeze, or prove complete change journal first. Freeze all cron/external schedulers/admin/favorites producers, drain in-flight jobs/leases and note final checkpoints; final export/import/verify; switch writer exactly once only after verified parity. Read-only Sites pages remain served. Minimum freeze duration is measured rehearsal export+import+verification time; no fabricated seconds guarantee. If export itself locks access, measure its real behavior before scheduling.
6. Rollback before destination writes: restore routing to unchanged Sites and resume old writers; retain original DB untouched. After destination writes start, DNS rollback alone loses new writes: stop destination writer, reconcile reverse delta or final snapshot with verified completeness, then resume source under separate approval. Keep immutable source export and change manifests; never delete source or apply dump restore during R3.

Completion evidence still missing: D1 identity/account/export authorization, complete DDL/FK/index inventory, DB size and exact full counts. No claim of a ready lossless migration until these are obtained.
