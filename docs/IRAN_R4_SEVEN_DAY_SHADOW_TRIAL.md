# 이란 전쟁 R4 — 7일 Shadow 임시운전 R1 (준비)

**적용 대상:** 작업 브랜치 `codex/iran-r4-seven-day-shadow-trial-20261018`의 연구용 순수 계산. 기존 공개 R3 점수·D1·SQLite 스키마·등록 작업·주기·DNS·배포는 변경하지 않는다. 7일 운영 **시작 확인 전**에 완료 상태라고 보고하지 않는다.

## 1주일 운영 계약

1. **시작 조건:** `r4-shadow-verified-input-v1`가 로컬 이란 SQLite checkpoint에 실제 존재하고, 각 전선(미국–이란·이란–이스라엘·예멘 후티), 호르무즈·홍해 항행, 핵 상태가 모두 개별 근거·유효시간·28일 관측 완전성 조건을 충족해야 한다. 원래 R1.3 `verified-input`를 자동 승격하지 않는다.
2. **Day 1:** 첫 유효 R4 입력을 PC에서 확인하고 `--sample`이 `SAMPLE_RECORDED`를 출력한 **한국시간 날짜**가 시작일이다. 예시로 10/18에 성공하면 10/18~10/24, 10/19에 성공하면 10/19~10/25. 단순 코드 병합일이나 계획일로 일주일을 시작하지 않는다.
3. **Day 1~7:** 매일 1개 **그날의 유효 입력·독립 증거 제약·Shadow 후보점수**만 저장한다. 결측·수집 실패는 50점으로 보충하지 않고 `R4_INPUT_PENDING`; 그날 실제 관측이 없으면 누락일로 남긴다. 같은 날 재실행은 기존 값을 덮어쓰지 않는다.
4. **동결:** 7일 중 가중치 20/35/25/10/10, 민감도 1.0, 계산기 코드 해시를 **고정**한다. 다른 계수 테스트는 **7일 후 사후 비교(원본 불변)**로 분리. 계산기 파일이 바뀌면 `R4_TRIAL_METHOD_OR_TUNING_DRIFT`로 차단한다.
5. **7일 후:** 관측 7개·검증된 독립 사건과의 모순·0/null/stale·출처 누락을 검토. **실제 기준 점수**가 독립 검증된 경우에만 오차 지표 계산. 기존 제안 18점에 맞추어 자동 학습/튜닝하지 않는다.
6. **다음 버전:** 별도 후보 가중치 및 민감도를 같은 7일 데이터에 재계산하여 비교한다. 사용자 승인 전 자동으로 운영 수치를 바꾸지 않는다.

## 계산과 로그

- 고정 R4 계산: `calculateIranR4RealityShadow` (기존 PR #400, 연구용)
- 7일 민감도 후보식: `q = Σ(w_i×D_i)/100; q' = clamp(0.5 + sensitivity×(q−0.5), 0,1); P' = L_phase +(U_phase−L_phase)×q'`. 100점은 검증된 종료 상태일 때만.
- Day 1 기본 sensitivity=`1.0`, 기본 가중치는 PR #400 후보를 그대로 사용. 숫자는 확정 운영 산식이 아니다.
- 입력 읽기: `E:\ZGmini\data\iran-progress-r13\iran.sqlite`의 **별도 검증 완료 checkpoint**만 읽기 전용. 없는 경우 시작하지 않는다.
- 경량 결과 원장: `E:\ZGmini\data\iran-progress-r13\shadow-r4-trial\week.json` — 7행 내외의 날짜, 구간, D/C/M/H/N 계산 결과, 입력 해시, 독립 관측 판정만 보존. 원문 기사·비밀키·원자료 복사 없음. 매일 안전한 임시 파일로 원자적으로 교체한다.
- 실행 로그: `%TEMP%\ZGMINI_IRAN_R4_SEVEN_DAY_SHADOW.txt` 1개만 덮어쓰기.
- API/Ollama/외부 호출: 0. D1 게시: 없음. Scheduler 등록·수정: 없음.

## CMD 실행 (대상 브랜치 소스가 PC 승인 worktree에 존재하는 경우에 한함)

```cmd
scripts\iran-progress\r4-seven-day-shadow.cmd --preflight
scripts\iran-progress\r4-seven-day-shadow.cmd --sample
scripts\iran-progress\r4-seven-day-shadow.cmd --report
```

- `--preflight`: 검증 완료 입력 유무·coverage 확인. 입력 checkpoint가 없다면 **기존 PC SQLite의 실제 저장 건수·후티 전선 누락·군사 7/21일 자료·Ollama 처리 현황을 집계**해 보여준다. 이 단계에서 결과 파일을 생성하지 않는다.
- `--sample`: 매일 한 번 실행할 때만 7일 결과 원장을 별도 저장. 자동 스케줄 미설치.
- `--report`: 진행·누락 날짜·후보 점수/반증 상태·정확도 미검증 여부 확인.
- `--compare`: 7개 관측 완료 후 `shadow-r4-trial\seven-day-variants.json`에 입력된 최대 12개의 **사용자가 명시한** 가중치/민감도 후보를 순수 재계산해 비교. 원본 `week.json` 변경 불가. 형식 예:
  `[{"name":"baseline","config":{"weights":{"D":0.20,"C":0.35,"M":0.25,"H":0.10,"N":0.10},"sensitivity":1}}]`

사후 비교 결과는 후보별 7일 점수뿐 아니라 **독립 교전 근거와 모순된 날짜 수**, **검증 불가 날짜 수**를 표시한다. 이를 근거로 자동 최적값을 선택하지 않으며, 임의의 18점을 정답 데이터로 넣지 않는다.

## 정확도 판정의 제한

- **1주일은 임시운전 관측 기간일 뿐**, 극단적 확전·실제 종전 등의 드문 사건까지 통계적으로 검증하기에는 부족하다.
- 변동 없는 기간만 보아 보정하지 않는다. 28일 시계열과 과거 주요 사건 리플레이는 별도 유지한다.
- 입력 데이터가 빠졌으면 진단을 보강해야 하며 임의 사건이나 가짜 휴전이력을 추가해서 READY 만들지 않는다.
- 실측값의 조정 전·후 비교는 오직 Shadow 기준. PC 실제 입력/로컬 결과 조회 → 최소 추가 검증 → 사용자 최종 승인 후 Production 전환.

**현재:** 구현 준비 / PC에서 `--preflight` 미실행 / 실제 7일 운전 미시작.
