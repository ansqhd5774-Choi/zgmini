# 이란 최근 14일 실제 게시 시각별 기록

2026-10-28 사용자 승인. 일별 추정 이력 `history` 14개와 실제 게시 시각별 `updateHistory`를 분리한다. 선형 변환·랜덤·스무딩·과거 중간값 재구성을 하지 않는다.

## 기록과 공개 계약

- 게시 시각은 `publishedAt`이며 기사 발표·발견·교전 발생 시각으로 설명하지 않는다. 한국시간 달력 오늘과 이전 13일 범위를 유지한다.
- `updateHistoryVersion=IRAN_PUBLISHED_UPDATES_R1`. 각 지점은 실제 게시 시각, 당시 점수, 수집 확인 시각, 원본 저장 checkpoint, 반영 사건 누계, 모델 계보를 포함한다. 마지막 지점은 현재 게시값과 정확히 일치해야 한다.
- 같은 점수의 새 게시도 기록한다. 재시도는 같은 시각의 같은 내용을 중복 저장하지 않는다. 같은 시각의 다른 내용은 충돌로 중단한다. 서로 다른 모델 계보를 연결하지 않는다.
- 다음 게시 직전에 실제 D1 저장본을 읽고 검증한 뒤 그 기록을 새 payload에 이어 붙인다. 원격 최신값보다 오래된 게시로 이력을 덮어쓰지 않는다. 원격 저장본이 손상됐으면 중단한다.
- 원격 쓰기 후 정확한 readback을 통과한 게시만 기존 PC `publications` 불변 원장에 추가한다. 새 테이블은 없다. 원격 게시 후 PC 기록 전에 중단돼도 다음 게시가 실제 원격 이력에서 복구한다.
- 일반 CLI는 publisher에 `store`를 전달해 PC 원장도 기록한다. 외부 고정 실행기를 전환할 때도 `publishIranR5Provisional(...,{now,store})`로 연결해야 한다. 기존 고정 승인 runtime을 임의 변경하지 않는다.
- 공개 구간은 최대 4096개 실제 지점이다. 초과 시 누락된 전체 이력을 완전한 것으로 표시하지 않고 명시적 오류로 중단한다. PC 원장 이전 기록은 삭제하지 않는다.

## 차트

UI 전용 브랜치의 공통 컴포넌트가 상세·요약 차트에 연결된다. 실제 기록이 있으면 갱신 시각별 선분과 지점을 표시하고, 기록이 없는 기존 payload는 기존 일별 표시를 유지한다. 지점 선택은 한국시간·점수·직전 게시 대비 변화와 사건 누계를 표시한다. 사건 누계는 그 게시의 원인을 단일 기사로 확정하는 표시가 아니다.

첫 기록 한 점으로 이전 14일을 채우지 않는다. 모델이 바뀐 첫 기록도 새 계보의 시작으로 표시한다. 기록이 늘어날수록 실제 시간대의 변화가 나타난다.

## 검증과 운영 상태

불변 누적·동일값·재시도·실패 게시 제외·KST 경계·구버전 호환·현재값 일치·원격 복구를 테스트한다. UI는 로컬 모의 자료를 실제 렌더링해 PC 및 모바일 폭과 선택 상태를 확인한다. 이는 실제 운영 수집/게시 검증이 아니다.

현재 main CI의 별도 테마 파일 누락 gate를 우회하지 않는다. reader 자동 배포·승인 PC runtime 전환·D1 readback·API 및 실제 화면 확인 후에만 운영 적용 완료로 보고한다. 스케줄을 바꾸지 않으며 공급자 수집을 강제 실행하지 않는다.
