# 게시 뉴스 → R5 점수 입력

- 페이지 `OutbreakNewsContainer`와 동일하게 `/api/outbreak-news/iran/r41`의 READY·7출처·양수 건수·배열 길이 일치 시 R41을 선택한다. 그 외에는 기존 `/api/outbreak-news/iran`을 선택한다.
- 원문 제목·출처·URL·발표일만 사용한다. 표시 impact, 번역문, 요약문은 점수 근거로 사용하지 않는다. 기존 R3_5 분류, R5_2 비중·민감도·기준점·중복 검토·이행 호재 검증은 유지한다.
- 기존 eventKey를 최초 전환 시 기준 이력으로 보존한다. 이후 비공개 수집 원장에 추가된 기사는 공개 뉴스로 승인되기 전 R5 신규 사건이 되지 않는다. 승인 URL은 14일 공개 목록에서 사라져도 누적 계산에서 제거하지 않는다.
- 과거 기사 지연 입수는 기존 0~1일 판정에 따라 보류한다. 최초 관측 시간을 소급하지 않으며 과거 실제 갱신 기록을 새로 만들지 않는다.
- 기존 원장·게시 이력은 삭제하지 않는다. 전환은 과거 14일 재산정이나 사건 재승인이 아니다.
- API 실패·빈 응답·잘못된 항목은 입력 checkpoint를 갱신하지 않는다. 기존 게시 입력이 없으면 중단하며, 있으면 그 입력을 보존한다. 비공개 후보 캐시로 대체하지 않는다.
- 공개 API 조회 시각은 수집 성공 시각이 아니다. 기존 수집 신선도 게이트를 갱신하거나 우회하지 않는다.
- UI·번역·뉴스 수집기·뉴스 D1 게시·예약 작업 등록은 변경하지 않는다. 기존 R5 예약 실행 wrapper의 입력 호출만 이 모듈로 교체한다.

검증: `node --test tests/iran-published-news-score-input-r1.test.mjs`.
실데이터 검산은 운영 SQLite를 read-only로 열고 별도 복제 DB에서 수행한다. 테스트 통과와 실제 PC 연결·D1 게시 검증은 별개다.
