# 신규 테마·산식 작업 공통 실행 지침

정본 브랜치: `codex/theme-fear-greed-integration-20261025`.
정의·구조 계약: [THEME_PLATFORM_STANDARD.md](THEME_PLATFORM_STANDARD.md).
실행 선택: [CMD_EXECUTION_PLAYBOOK.md](CMD_EXECUTION_PLAYBOOK.md).
이 문서는 앞으로의 테마 추가·일괄 산식 전환용이며 데이터센터만의 복구 절차가 아니다.

## 시작할 때 한 번 확인

1. 원격 작업 브랜치/실제 운영 소스/현재 변경 상태를 구분한다. 이미 검증된 Runtime·원본 증거는 재사용한다.
2. 사용자가 요청한 테마/산식/공개 범위를 적는다. 불분명한 결정만 한 번 질문하고 독립 작업은 계속한다.
3. 기존 등록·입력·AUM·산출물·공개 승인 자료를 찾아 재사용한다. 동일 내용을 다시 만들지 않는다.
4. 설정→입력→계산→게시→Reader→예약의 기존 공통 경로와 차이만 계획한다. 테마별 CMD·태스크·API·게시기를 자동 생성하지 않는다.

## 기본 위임과 실제 권한

`config/theme-platform-delegation.json`은 2026-10-31 사용자의 공통 체계 작업 위임 범위를 기록한다. `theme-platform-policy.mjs`는 수행 여부를 판정한다. 이 파일은 인증 수단이나 공급처 배포권 증명서가 아니다.

| 작업 | 처리 기준 |
|---|---|
| 기존 자료 조회·차이 분석·계획·테스트·문서 정정 | 요청 범위 안이면 재승인 없이 진행 |
| 후보 조사·저장 입력 수집·비공개 계산 | 이미 승인된 기준/공급처/비용/테마 범위 안이면 진행 |
| 설정 등록 | 검증된 선정·산식 계약 사용. 임의 ETF/가중치 결정 금지 |
| 기존 전용 브랜치 commit/push | 본 작업 파일만 선택, 보호 main/전체 병합과 구분 |
| 검증된 결과 게시·전환 | 사용자가 승인한 공개 범위·실제 권리 근거·Reader 계약이 유효하면 반복 질문 없이 진행 |
| 비용·새 계정 약관·권한 확대·파괴적 변경 | 기존 위임으로 추정하지 말고 필요한 결정만 확인 |

새 테마마다 동일 공급처의 같은 권리 검토를 처음부터 반복하지 않는다. 적용 계정·요금제·출력 종류·약관 버전·유효 범위가 같은 기존 근거를 재사용한다. 변경점이 있을 때만 해당 부분을 확인한다. 일반 위임이나 사용자 위험 동의를 법적 권리의 대체 증거로 쓰지 않는다.

공통 자동화 계정은 필요한 원자료 조회·승인된 결과 key 게시 범위로 제한한다. OS 관리자/DNS/결제/전체 Cloudflare 계정 권한을 신규 테마마다 요구하지 않는다. 기존 자격증명 경로를 재사용하며 사용자가 Secret을 채팅에 붙이도록 요구하지 않는다. 이 구현 단계에서는 실제 IAM/토큰 권한을 변경하지 않는다.

## 반복 작업을 줄이는 순서

- 테마는 등록 데이터, 산식은 버전별 코드 바인딩, 공급처는 공통 어댑터로 처리한다.
- 후보 ETF 수/테마 수 상한을 설정하지 않는다. 적격성 기준이 최종 명단을 결정한다.
- 전체 목록을 대상으로 계획하고 공급처별 공유 ETF/SPY 입력은 중복 수집하지 않는다.
- API 예산·실행 시간·페이지 크기는 설정 가능한 자원 정책이다. 부족하면 cursor/checkpoint를 저장하고 남은 테마부터 이어간다. 테마를 삭제·제외하거나 상한을 늘리는 코드 수정으로 해결하지 않는다.
- 산식 변경 시 적용할 전체 ID 집합을 확정하고 기존/신규 산출물을 동일 입력으로 비교한다. 공통 코드 한 번과 설정으로 여러 테마를 처리한다.
- 공개 API/등록 명단 차이, 산식 버전, 확정/잠정 입력·계산·게시 lineage를 자동 대조한다.
- 이미 완료된 항목은 증거 참조로 유지한다. 새로 바뀐 범위만 검증한다.

## 장애는 다음 행동까지 보고

| 상태 | 행동 | 금지 |
|---|---|---|
| PC 자동화 접근 불가 | 기존 파일 전달 또는 검증된 ZIP/CMD 1회 경로 | PC 장애로 단정, Codex만 가능하다고 종료 |
| 정상 실행 lease | 상태 조회 후 정상 해제 대기·재개 | 강제 종료/잠금 삭제 |
| 공급처 최신일 미제공 | 실제 날짜 보존·정책 재확인 | 가짜 점수/날짜, 영구 확인완료 처리 |
| 호출 예산 부족 | 다음 예산 구간 cursor 재개 | 테마 총량 제한 |
| 설치 source SHA 차이 | 차이 비교·기존 변경 보존·선별 적용 | hash 검사 삭제/무조건 덮어쓰기 |
| main과 작업 브랜치 분기 | 필요한 파일만 비교·기존 승인 통합 경로 사용 | 전체 브랜치 병합·무승인 강제 push |
| 기존 CI 실패 | 기준선/변경 영향 분리·정확히 기록 | 테스트 약화, 무관한 수정 추가 |
| 승인·권리 근거 부족 | 부족한 범위만 질문·다른 작업 지속 | 전체 프로젝트 차단·동의 위조 |
| 게시 결과 불확실 | CAS/readback/기존 결과부터 확인 | 같은 쓰기 무조건 반복 |

모르는 오류를 위 표의 정상 대기로 임의 분류하지 않는다. 정확한 첫 실패 단계와 원본 오류를 보존한다. 자격증명·원자료 전체는 진단 보고에 넣지 않는다.

## 일반챗의 실행 도구 선택

기존 CLI 호출, 저장 결과 읽기, 독립 Node/PowerShell 검사, ZIP+manifest, 단계별 CMD, 사용자 1회 실행을 필요에 따라 조합한다. 한 개 거대 CMD에 모든 코드를 넣을 필요가 없다. 프로젝트 Windows 실행 제한(CMD-only 등)은 해당 환경 규칙을 우선한다.

현재 저장소 공통 source 진단:
`node scripts/pc-writer/theme-config-tool.mjs --platform-inspect`

새 테마는 `ZGMINI_THEME_CONFIG_V2`와 기존 R32를 사용한다. 선정 증거는 `ZGMINI_THEME_SELECTION_EVIDENCE_V1`(themeId, selectionApproved, 실제 승인/정책 참조, rows의 ticker/공식 holdingsUrl/providerLookupVerified/operatorGrade), AUM 증거는 `ZGMINI_THEME_AUM_EVIDENCE_V1`(themeId, 실제 승인/정책 참조, datedOfficialAumApproved, rows의 ticker/aumUsd/aumAsOf/공식 sourceUrl)로 보존하고 SHA를 등록 명세에 연결한다. 기존 유효 근거를 재사용하며 샘플 승인 문구를 실제 승인으로 쓰지 않는다.

V2는 별도 원천 가격 수집 함수를 만들지 않고 기존 공통 collector를 호출하고, R25→R32를 사용한다. 기존 공통 예약의 자동 게시가 확정·잠정을 차례로 처리한다. 잠정은 기존 MarketParquet 저장 자료와 검증된 overlap만 사용하고 없으면 정상 대기한다. `examples/theme-registration-r32.template.json`은 개발자용 형식 예시이며 그대로는 검증에 실패한다. 일반챗은 근거가 채워진 완성 JSON과 실행 파일을 제공해야 하며 사용자가 코드/경로/SHA를 직접 편집하도록 요구하지 않는다.

V1은 과거2종 profile 보존용이다. V2가 실제 설치/배포됐는지는 ACTIVE_RUNTIME·설치 SHA·공개 `/api/theme-configured` 지원 정보로 구분한다. 업데이트는 기존 설치기 기반 반복 갱신을 사용하며, 이전 한 번 설치 성공 기록을 삭제해 우회하지 않는다.

수동 실행이 필요한 경우 목적/준비상태/폴더/파일/입력/1회 실행/정상값/STOP 조건/금지행동/보낼 결과를 함께 안내한다. 자동화가 막혔다는 이유로 이미 성공한 Production 검증을 다시 요구하지 않는다.

## 완료 보고는 증거 단위로

구현·테스트·commit/push·설치·D1 readback·공개 결과·자연 예약은 각각 기록한다. 파일 수·HTTP200·빌드·테마가 보인다는 사실만으로 전환 완료를 선언하지 않는다.
구조 개선 완료는 새 등록이 공통 경로를 실제로 통과하고 기존 결과를 보존하는 것으로 판단한다. 실제 테마를 임의 공개하거나 샘플 데이터를 Production에 쓰지 않는다.
