# D1 요청 중 인증 만료 방지

## 확인된 장애와 한계

2026-10-26 18:30 KST 정규 게시는 시장 점수 저장 이후 13개 후속 조회에서 D1 HTTP 403을 기록했다. 18:33 기존 Wrangler 인증이 갱신된 후 같은 D1 조회가 성공했고, 시장 점수 12개와 PC 원장 해시·저장 시각이 일치했다. 실패 당시 인증 만료 시각은 사건에 보존되지 않아 403의 직접 원인을 만료로 확정하지 않는다.

설치된 Wrangler 코드는 `whoami`에서 만료된 OAuth만 갱신한다. 기존 `credential()`의 만료 5분 전 호출은 갱신을 보장하지 않았으며, 게시 시작 시 인증값을 고정해 실행 도중 만료를 처리하지 못했다. 이 확인된 결함을 수정한다.

## 처리 계약

- D1 공통 client는 문자열 인증값과 요청 시 호출하는 인증 함수를 지원한다. 직접 공통 client를 사용하는 운영·복구 게시/조회 경로는 함수로 연결한다.
- 매 요청 직전 기존 공식 Wrangler 인증 상태를 확인한다. 만료 시 기존 Wrangler 갱신 경로를 사용하며 새 로그인·권한·별도 키를 만들지 않는다.
- 조회가 401/403이면 인증 함수를 다시 확인한다. 실제 인증값이 바뀐 경우에만 최대 1회 재조회한다. 같은 인증값·고정 API 토큰·갱신 실패·두 번째 실패는 중단한다.
- 조회 재시도는 통신 복구와 합쳐 최대 2회 요청이다. 쓰기는 인증 오류에서도 자동 반복하지 않는다. 기존 고유 lease/게시 원장 readback 계약을 유지한다.
- 인증값·헤더·원문 오류는 보고서에 기록하지 않는다. `authReadRetries` 숫자만 추가한다.
- 산식·가중치·TTL·스키마·UI·스케줄은 변경하지 않는다. 별도 테마 전용 transport는 이번 수정 대상이 아니다.

## 검증 구분

만료 경계 모사, 요청 사이 인증 변경, 변경 없는 403 차단, 쓰기 무반복, 갱신 후 두 번째 실패 중단을 단위 검사한다. fixture 통과를 실제 OAuth 만료를 통과한 운영 증거로 간주하지 않는다. PC 설치 후 정규 실행 및 D1/공개 API 검증은 별도 기록한다.
