# 이란·주변 분쟁 보도 흐름 R3

2026-10-18 사용자 승인 개편안의 1차 운영 반영이다. 전체 전쟁 강도나 종전 확률을 산출하는 모델이 아니다.

## 숫자 계약

- 기존 외교30/휴전25/군사20/해상15/핵10%와 기준점50, 표시 배율1을 유지한다.
- R2의 단계 가감점은 유지한다. 요격은 군사 영역 −4로 구분하며, 실제 공격 −12와 공격 예고 −2를 섞지 않는다.
- 각 날짜의 사건을 합산한 뒤 영역0~100으로 제한하고 가중합한다. 기사 순서와 같은 사건의 출처 수로 점수가 커지지 않도록 중복 후보를 보류한다.
- 새로운 입력 없는 시간 경과만으로 점수를 올리거나 내리지 않는다. 수집 실패를 완화 신호로 쓰지 않는다.
- R3 원장·checkpoint·공개 key `public:iran-progress:reference-flow:r3`는 R1/R2와 분리한다. R3 과거 차트는 동일 R3 규칙의 보관 기사 발표일 기준 재구성이며 실제 과거 공개 점수나 사건 발생일이 아니다.

## 수집·분류

- 이란 직접 전선과 후티·예멘·사우디·홍해·바브엘만데브를 포함한다. 다른 분쟁은 이란 관련성이 없으면 제외한다.
- 기존 Tasnim·영국 정부·IAEA 외 BBC 중동 RSS, 알자지라 RSS, UN 중동 RSS를 추가한다. 공개 RSS 제목·요약·링크·발표일만 저장하며 유료 본문을 우회하지 않는다.
- 공식 RSS endpoint의 실제 응답·형식·날짜를 검증한다. 검색 결과를 운영 사건으로 직접 넣지 않는다.
- 행위자/대상/장소/발표일/근거 제목을 저장한다. 발생일을 확인하지 못했으면 eventDate=null이며 발표일로 위조하지 않는다. 피해 규모는 추정하지 않는다.
- 요약은 지역·행위자 맥락에만 쓰고 실제 행위는 제목에서 확인한다. 예측·부정·불명확한 복수 단계·질문·분석 제목은 보류한다. 공격 예고는 실행 공격으로 처리하지 않는다.
- 같은 규칙·3일 이내 제목 토큰 유사도0.55 이상은 중복 후보로 보류한다. 다른 명시적 장소·대상·행위자는 합치지 않는다. 이는 사건 동일성의 사실 확인이 아니며 보류 기록을 남긴다.
- 한 출처 실패 시 나머지 출처의 신규 자료 처리를 계속하고 UPDATE_DELAYED 및 출처별 실패를 표시한다. 발견 실패·대기·점수 동일을 구분한다.

## 표시·한계

- 미관측 영역과 포화 영역을 명시한다. 미관측 50점은 평온/중립이 관측됐다는 뜻이 아니다.
- 마지막 수집 확인 시각과 마지막 반영 보도일을 분리한다. 공식 교전 종료 확인이나 모든 사건의 포괄성을 주장하지 않는다.
- AIS는 2026-10-18 사용자 승인으로 정기 수집에서 제거했다. `ais`·`aisHealth`의 과거 실패 기록은 활성 수집 상태 집계에서 제외한다. 기존 AIS 원장·checkpoint·과거 산식 재현 모듈은 보존한다. AIS 중단은 통항 정상화를 뜻하지 않는다.
- 해상 위험 대안은 기존 MARAD 공식 경보 및 UKMTO 사고 보고를 우선 검토한다. 이는 AIS 통항량 대체 자료가 아니며, 미발표·경보 만료를 공격 0건이나 정상화로 해석하지 않는다. 승인된 R3 가중치·단계 점수는 변경하지 않는다. 새로운 자동 점수 입력은 출처·발표일·중복·분류 검증 후 별도 적용한다.
- 누적 점수의 포화 문제는 진단으로 노출한다. 이번 정체의 직접 원인은 포화가 아닌 수집·분류 누락이므로 임의 감쇠·기간·재가중치를 추가하지 않았다. 새 수치 산식이 필요하면 별도 비교·버전으로 검증한다.

## 검증·전환

운영 DB 복사본의 실제 RSS 수집 및 같은 입력 재검산에서 R2 44.7/5사건, R3 41.9/7사건이었다. 이는 정확도나 전체 전쟁 포괄성을 입증하는 수치가 아니다.
기존 세 영역은 여전히 미관측이며 그 한계를 UI에 노출한다.

신규 분류·중복·결측·부분 실패·별도 게시 key·reader fail-closed 테스트와 기존 이란 회귀 검사 후, GitHub main→Cloudflare Git integration으로 reader를 배포한다.
배포 reader R3 확인 뒤 R3를 게시하고 readback/API/화면을 검증한다. 기존 작업 시각은 유지하며 R3가 기존 AIS 수집보다 먼저 게시된다.
R1/R2 공개값·원장·checkpoint와 이전 launcher를 보존한다. 잘못된 R3를 R2 정상 결과처럼 숨기지 않는다.

## R3_2 분류 보정

저장된 BBC의 후티 대통령궁 사망 보도와 아람코 건물 피격 보도가 기존 제목 패턴에서 누락됐다. `Yemeni` 지역 표기, 피해 동사를 동반한 명사형 미사일·드론 공격, 건물 피격을 인식한다. 반대로 `: What that means` 해설은 새 공격으로 계산하지 않는다. 무기보다 실제 피격 대상을 우선 기록한다. 경고 제목의 요약에 과거 공격이 있어도 실행 공격으로 승격하지 않는다.

동일 저장 자료 재검산은 기존 R3_1 41.9/7사건에서 R3_2 39.5/8사건이다(공격 2건 추가, 해설 1건 제외). 가중치·단계 가감점·기준점·스케줄은 그대로이며, 이 값은 전체 전쟁 상황의 검증된 강도 지수가 아니다. 분류 버전을 올려 기존 제외 판정도 재검토한다.


## R3_4 예멘·사우디 및 당일 잠정 자동 갱신 후보 — 2026-10-21

- 범위: 기존 후티/예멘/사우디 관련 제목 중 군사훈련시설·야전 캠프·도시·주거지역·타이즈·샤브와·카미스무샤이트 공격 보도 인식 보완. `attack` 단수형 누락을 수정한다. 실제 공격 −12, 요격 −4, 5영역 비중, 중복 보류 및 불명확 기사 제외는 유지한다.
- 분류 버전은 `IRAN_EVENT_RULES_R3_4`로 독립시키고 기존 R3_3 원장·의사결정·원본 점수를 임의 덮어쓰지 않는다. 기존 출처가 실제 보도를 발견하지 못한 경우에는 사건을 추정·생성하지 않는다.
- 수집·계산의 최근 14일 기준 날짜를 화면과 동일한 **KST 달력**으로 맞추고, R3 공개 검증기에서도 한국시간 자정 직후 자료를 미래 관측으로 기각하지 않도록 정렬한다. 기사별 발표일 원자료는 별도로 보존하며 교전 발생일로 위조하지 않는다.
- 수집 대기 개수는 현재 14일의 미처리 항목만 집계한다. 기간 밖 항목은 로컬 저장 상태 그대로 보존하고 신규 수집 성공/실패를 바꿔치기하지 않는다.
- 화면의 2026-10-19 잠정 19점 앵커는 그대로 보존하고 신규 R3_4 발표일 변화량만 10월 19일 이후 표시 점수에 반영한다. 임의 전황 실측·종전 확률이나 별도 R4 산식으로 격상하지 않는다.
- 기존 R3 자동 작업 엔트리 `scripts/iran-progress/run-reference-flow-r3.mjs`는 뉴스 수집 → 로컬 계산 → 기존 D1 공개 키 게시/재조회 후 레거시 수집기를 실행한다. `install-reference-flow.mjs --collector=<기존 승인 collector 경로> --r3`는 기존 작업 등록·주기를 바꾸지 않고, **기존 launcher와 이전 R3 게시 검증이 확인된 경우에만** R3 엔트리로 연결한다. 기존 런처는 `.before-reference-r3`로 보존하며 R2 설정은 `--legacy-r2`로 전달한다.
- 새 작업 등록, GitHub Actions 기반 수집, Cloudflare Cron, 신규 유료 API, 신규 공급자 RSS, 외부 DB, 산식·가중치 변경은 모두 없다.
- **별도 운영 Gate**: 실제 PC Windows 작업 XML/launcher/운영 source SHA 읽기 → 기존 스케줄·최근 실행 검증 → 수정본 동일 PC 소스 테스트 → 승인 범위의 연결 → 다음 정규 실행 및 로컬 checkpoint/원격 D1/API/UI read-back. 이 검증 없이 자동화 완료 또는 신규 전황 반영 완료를 선언하지 않는다.
- **커버리지 한계**: Reuters/AP/SPA 기사는 기존 승인 RSS 목록에 직접 포함돼 있지 않다. 따라서 보도 존재만으로 해당 사건이 R3에 포함될 것을 보장하지 않는다. 확장은 무료 상업 재이용 권한·엔드포인트·호출 제한 검증 후 별도 승인 범위에서 진행한다.
