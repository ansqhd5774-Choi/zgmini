# R32 기업 실적 우선 정렬·중복 검토 (2026-10-29)

## 작업 경계

- R31 PC 설치 성공 로그에서 신규 PC 커밋 `4466f602abfe09bb9cc7530fd109ba1d80aeacbd`, 정확히 두 파일 변경, 강제 수집·게시 없음 확인.
- R30은 이미 핵심 기업 우선 정렬과 최신 14일 전체 스냅샷 교체를 구현한다. R32는 이 수집 절차를 변경하지 않는다.
- R32는 **기존 D1 표시용 HTML 저장본을 읽는 사이트 단계**에서만 우선 표시·중복 검토를 수행한다. 새 PC CMD/설치, 신규 외부 요청, 예약 작업, DB 스키마 변경은 필요하지 않다.

## 표시 규칙

1. 미국 핵심 기업 8개 발행사(NVDA, AAPL, MSFT, Alphabet의 GOOG/GOOGL, AMZN, META, TSLA, AVGO)는 동일 일자 내 우선 정렬하고 `핵심기업` 꼬리표를 표시한다.
2. **같은 날짜·같은 티커**의 반복은 화면에서 1건으로 합친다. 내용까지 완전히 같으면 추가 경고 없이 하나만 표시한다.
3. 같은 날짜에 상충하는 장전/장후 정보가 반복되면 **시각 미정**으로 표시하고 `동일 날짜 정보 상충`을 명시한다. 임의로 시간을 선택하지 않는다.
4. **서로 다른 날짜에 같은 티커**가 나타나면 정정 여부를 제공원이 확정하지 않았으므로 날짜를 자동 선택하거나 삭제하지 않는다. 두 건을 유지하되 `여러 날짜 중복 · 확인 필요`로 표시한다.
5. API 검색·날짜 선택 시 날짜별 건수 헤더는 전체 조회 기간에 대한 건수를 유지한다.

## 한도·권리·상태

- EarningsAPI 공식 자료는 장전·장후·시각 미정을 구분한다. 이 필드는 기업 공식 확인과 같지 않으므로 `예정 · 미확정` 표시를 유지한다.
- 기존 원문 수집일 기준 매일 최대 14회 설계는 변하지 않는다. R32는 저장본 HTML만 조작하므로 **추가 공급원 API 호출 0회**.
- 같은 종목이 여러 날짜에 걸쳐 나타나는 원자료 자체는 삭제·변경하지 않으며, 업데이트되면 R30 전체 스냅샷 교체에 따라 과거 날짜가 빠진다.
- 기존 `/api/release-calendar` 원문 경제지표는 변경하지 않는다. R31 HTML-only 권리 경계 유지.
- SEO: 별도 페이지 생성·메타/타이틀 변경 없음. HTML 응답 `noindex` 유지.
