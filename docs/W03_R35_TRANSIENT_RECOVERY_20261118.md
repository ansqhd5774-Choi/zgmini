# W03 SPY 수집 중단: 일시 오류 복구 (2026-11-18)

## 실제 확인

- 기존 예약 실행의 HTTP 404 이후, 설치 #2049로 `stocks/us` 경로가 반영됐다.
- 기존 예약 단회 시작 #2066은 실제 실행됐으나 `STOP_NETWORK_OR_TIMEOUT`으로 끝났다. 신규 SPY 저장 성공은 아니다.
- 동일 무료 bars 경로의 비인증 HEAD는 HTTP 502 / Retry-After 60을 반환했다. 홈페이지 HTTP 200과 수집 API 정상은 별개다.

## 최소 변경

- R35: 429/500/502/503/504 및 연결 실패를 재개 가능한 GET 실패로 분리한다. 기존 4회/배치·최대 64배치 안에서 전체 실행당 재시도 최대 2회, 최소 60초 및 Retry-After 준수. 5분 초과 대기는 재시도하지 않고 반환한다.
- 저장된 checkpoint는 원자료 SHA·manifest·대상 구간 검증을 통과한 후 같은 cursor에서 재개한다. 실행 결과 불명확, 데이터 검증 실패, 404 등은 여전히 중단한다. 공급자 대기 시각은 checkpoint에도 보존한다.
- R47: 연결/일시 HTTP 실패를 성공한 최신성 조회와 구분하여 6시간·하루 2회 최신성 제한에 포함하지 않는다. 실제 신규 봉이 없는 성공 응답의 제한은 유지한다. 기존 원장과 완료 페이지는 삭제하지 않는다.
- CMD 16개 payload 중 R35와 PLANNER만 변경한다. 기존 산식·ETF·예약 정의·공개 승인·D1 동작은 변경하지 않는다.

## 8개 제한에 대한 범위 판단

SPY와 ETF 독립 수집, 테마별 준비 상태 계산은 별도의 수집/계산 계약 변경이며 이번 일시 오류 수정 완료 조건에 추가하지 않는다. 무료 sample 경로는 유료 query 경로의 300회/분과 다르므로 이를 근거로 속도를 높이지 않는다. 7일 구간과 19시 기준은 이번 연결 실패의 직접 원인으로 입증되지 않았다. 원자료 SHA·OHLCV·중복/시간 정렬·checkpoint 보호 및 데이터 권리 제한은 유지한다.
