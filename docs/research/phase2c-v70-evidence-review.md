## 4. 정의 변경 처리 설계 — 실행하지 않음

A. 동일 정의로 소급 수정된 공식 이력이 있으면 원본·수정본을 별도 보존하고 획득시각, 출처, 단위, revision을 기록한다. 수정본 기반 hindsight 연구와 당시 공개값 기반 point-in-time 연구를 분리한다.

B. 정의가 다르고 소급본이 없으면 regime을 분리한다. 이동평균뿐 아니라 252개 percentile 입력 전체가 같은 정의여야 한다. L0는 252개, L3는 254개, L5는 256개의 연속 유효 동일 정의 관측이 필요하다(0-based 첫 위치 251/253/255). 결측이 있으면 더 늦어질 수 있다. 252 달력일로 바꾸거나 표시 시작일만 이동해서는 과거 정의 입력이 제거되지 않는다.

C. 적용범위·소급정책 미확인이면 현재 비교 가능성 미확인 상태를 유지한다. API 연결 성공을 경제적 비교 가능성으로 승격하지 않는다.

기사 금액 대입, 특정 증권사 금액 차감, 급변일 삭제, 0 대체, 임의 비율 연결은 하지 않았다. 원자료 미확보이므로 변경 전후 실제 값·단위·반올림 대조도 미수행이다.

## 10. 후속 사용자 결정에 따른 제한형 진행 정책

위 1~9절은 이전 검토 기록이다. 이후 사용자는 기관 문의·답변 대기를 현재 개발 경로의 선행조건에서 제외하고, 미확인 조건을 필요로 하는 사용 범위를 줄이도록 승인했다. 이전 UNCONFIRMED와 미발송 문의 초안은 보존한다. 현재 NEXT는 기관 문의가 아니라 제한형 구현의 검증 후 REMOTE PUSH다.

새 서버 프로필 FSC_SCOPED_INDICATORS_V1 / fsc-scoped-1은 FSC 신용융자와 반대매매만 사용한다. BOK 입력·캐시·점수·상관·종합모형은 HTTP 경로에서 제외한다. BOK 권리 미확인은 금지 확정도 허가 확정도 아니며 productionEligible=false를 유지한다. KOSIS·CMA·3축 composite·weight grid도 이 경로에서 실행하지 않는다. 기존 연구 함수는 회귀용으로 보존한다.

반대매매는 예방적 경계 20231025로 입력부터 자른 후 모든 검증·L3 평균·252 percentile 상태를 새로 만든다. apiChangeConfirmed=false, historicalBackcastConfirmed=false, seriesComparability=UNCONFIRMED를 유지한다. 알려진 결측 슬롯은 남기고 주말·휴일 슬롯을 추측해 추가하지 않는다. 결측 없는 경우 254번째 원시 관측부터 가능하며 달력일 기준이 아니다.

공개 계약은 개별 보조지표이며 종합점수·최종 가중치는 null이다. 신용은 기존 LEV_BLEND20_60, 반대매매는 기존 inverse L3를 한 번 뒤집은 pressure 방향이다. 금액 단위는 null이며 상대 점수는 확률이 아니다. 수학적 계산 가능성과 장기 검증 충분성은 별개다.

현재 확보한 원자료의 재구성으로 명시하고 sourcePublishedAt=null, pointInTimeVerified=false, historicalVintageVerified=false를 유지한다. fetchedAt은 원자료 수신 후 시각이며 캐시 응답에서 덮어쓰지 않는다. 로컬 fixture 검증만으로 runtimeVerified/releaseReady를 true로 바꾸지 않는다.

범위 확대 때에는 기존 통계 정의·공표시점·빈티지·항목별 이용권 검토를 다시 적용해야 한다. 이 구현은 기존 3축 지수 공개 승인이나 모든 미확인 문제의 해결을 뜻하지 않는다.
