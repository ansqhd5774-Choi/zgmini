## 1. 승인된 보관·표시 기준

| 자료 구분 | 기간 | 만료 처리 |
| --- | --- | --- |
| 사이트 주요 뉴스 표시 | 최근 14일 | 노출 대상에서 제외 |
| PC의 **뉴스 표시 전용** 자료 | 30일 | 만료 자료 자동 삭제 |
| 뉴스 표시 전용 중복 처리 임시 기록 | 30일 | 참조 안전성 확인 후 자동 삭제 |
| 전쟁 점수 산출·검증에 필요한 원장/근거/이력 | 기존 승인 보관 정책 | 뉴스 표시용 보관 만료만으로 삭제 금지 |

- 이 정책은 새로 연결하는 **뉴스 표시 계층**에 한정한다. 기존 이란 R3/R5 사건 원장, 검증 증거, 공개 이력, SQLite 원자료, 기존 공통 16개월 보관 정책을 일괄 변경하지 않는다.
- 사이트에 보이는 `0건`은 실제 표시 대상이 0건일 때만 표시한다. 임의 뉴스나 요약을 채우지 않는다.
- 기사 발표 시각(`publishedAt`)과 PC 수집 시각(`collectedAt`), 검증·게시 시각을 구별한다. 만료 판단의 기준은 검증된 기사 **발표일**이며, 시간대는 KST로 일관되게 적용한다.
- '최근 14일'은 기준일 포함 최근 14개의 KST 날짜, '30일 보관'은 기준일 포함 최근 30개의 KST 날짜를 가리킨다. 발표일 누락·불명확·미래인 기사는 임의 날짜를 생성하여 공개하지 않는다.

## 2. 자동 정리 범위와 안전 장치

1. 기존 승인된 PC 뉴스 수집·게시 사이클에 표시용 데이터 정리를 연결한다. **신규 스케줄러, Cloudflare Cron, 재수집 작업을 추가하지 않는다.**
2. 정리 전 **표시 전용 자료**인지 식별하고, 검증 원장·이력·활성 checkpoint의 참조 여부를 확인한다.
3. 만료된 표시 전용 자료만 제한된 배치와 트랜잭션으로 삭제한다. 참조 대상이거나 분류가 불명확하면 삭제하지 않고 별도 사유를 기록한다.
4. 같은 실행에서 정리 전후 건수, 만료 후보, 실제 삭제 건수, 실행 시각, 실패 사유를 기록한다. 로그에 기사 전문·키·개인정보를 쓰지 않는다.
5. PC에 저장된 표시용 결과를 재조회한 다음 기존 승인된 공개 결과 게시 경로로 반영한다. 사이트의 만료 기사가 재등장하지 않도록 읽기 경로도 기간 필터를 적용한다.
6. 최초 실운영 삭제 전에는 대상·참조·복구 가능성을 확인하는 dry-run을 거친다. 기존 이란 DB·checkpoint·점수 원장을 범위로 하는 광범위 DELETE/초기화는 금지한다.

SQLite에서 행 DELETE 후 파일 용량이 즉시 감소하지 않을 수 있다. `VACUUM` 또는 DB 설정 변경은 이 정책의 자동 구현 범위에 포함하지 않는다.

## 3. 뉴스 수집·공개 조건

- 기존 GDELT·RSS 이란 수집 경로를 먼저 확인한다. 신규 API 추가는 별도의 무료·상업적 이용·파생 공개·저장 재공개 권리 검증을 통과한 경우에만 진행한다.
- 외부 기사의 출처·링크가 있다는 이유만으로 본문·사진·원문 요약 재게시 권리가 있다고 보지 않는다.
- UI의 기존 `OutbreakNewsItem` 입력 계약(`id,source,publishedAt,title,summary,impact,sourceUrl`)과 전체/긍정/부정 필터를 보존한다. 실제 데이터 매핑과 요약·영향 분류는 근거와 이용권 검증 후 별도로 구현한다.
- 기사 영향은 전쟁 **종전 진전**에 대한 참고 분류이며, 긍정/부정 감정 점수나 전쟁 점수 변동의 직접 원인으로 간주하지 않는다.
- 승인 없이 점수 산식·가중치·원장·DB 스키마·TTL·PC 작업 주기·배포 설정을 수정하지 않는다.

## 4. 최초 수립한 구현·검증 체크리스트 (2026-10-26 기준)

아래 체크리스트는 **원안 당시 이력**으로 보존한다. 이후 코드 구현·PC 설치·일회 게시가 이루어졌으므로 현재의 완료 상태를 이 과거 체크리스트만으로 판정하지 않는다. 최신 단계별 PASS 기준은 구현 작업 계획 §32를 따른다.

- [ ] 표시 전용 저장 경로와 기존 이란 원장 간 참조 관계 확정
- [ ] 14일 공개 필터와 30일 PC 표시용 만료 처리 구현
- [ ] 경계일, 중복, 발표일 누락, 날짜 갱신, 실패·재시도, 검증 원장 보존 자동 검사
- [ ] 실제 운영 삭제 전 dry-run에서 정확한 대상만 식별했는지 검증
- [ ] PC 수집 → 로컬 저장 재조회 → 허용된 공개 게시 → 공개 API/UI 재조회
- [ ] PC·모바일 필터·뉴스 건수·원문 링크·만료 후 재출현 여부 확인
- [ ] 필요한 별도 승인 후 PR/CI → GitHub `main` → Cloudflare Git Integration 배포와 Runtime 확인
