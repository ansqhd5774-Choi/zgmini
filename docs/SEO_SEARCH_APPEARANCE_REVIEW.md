# ZGMINI 검색결과 제목·설명·유입 개선 상시 점검 기준 R1
개정: 2026-10-25 · 사용자 승인 범위: ZGMINI 페이지 신규 제작·수정·검토 시 반복 적용

## 1. 목적과 적용 시점
- ZGMINI 사이트의 **실제 페이지**를 신규 제작하거나 UI·문구·콘텐츠·검색 관련 설정을 수정할 때, 해당 URL의 Google 검색결과 **제목 링크(title link)**·**설명문(snippet)**·노출 가능성·클릭 유입을 함께 점검한다.
- 페이지 변경 PR의 정규 검토 과정에 SEO 점검을 포함한다. 관련 없는 서버 수집·산식·DB 작업만 할 때는 페이지 SEO를 억지로 변경하지 않는다.
- 사용자 제공 검색결과 화면은 **제목/설명이 노출되는 위치의 예시**다. 화면에 나온 사과 등의 예시 소재를 ZGMINI에 추가하지 않는다.
- 목표는 투자자의 검색 의도와 실제 페이지 내용을 잘 연결해 **관련 검색 노출과 자연스러운 클릭을 개선**하는 것이다. 순위·노출·CTR 상승을 보장하거나 미측정 상승을 보고하지 않는다.

## 2. 사전 확인
1. **페이지 URL·역할·검색 의도**를 식별한다. 예: 섹터별 공포탐욕지수, 미국 경기침체 지표, 테마별 시장 심리 등 해당 페이지가 실제 제공하는 내용만 검색어 후보로 고려한다.
2. 가능하면 **Google Search Console(GSC)**에서 URL·쿼리별 노출수/클릭수/CTR/평균 게재순위를 확인한다. 기존 AGENTS.md의 GSC Wizard 우선 및 비용 제한 규칙을 지킨다. 접근/자료가 없으면 `NO_GSC_EVIDENCE`로 기록하고 성과를 추측하지 않는다.
3. 공개 페이지의 HTTP/index 가능성, 실제 DOM head 메타데이터, 화면 H1, 본문 첫 설명, 내부 연결을 확인한다. GitHub 코드에 쓰인 문자열만으로 공개 반영을 단정하지 않는다.
4. 고유한 검색 의도·우선순위 검색어·현재 표현의 불일치를 판단한다. 현재 설정이 충분히 적절하면 **NO_CHANGE**를 정상 결과로 인정한다.

## 3. 검색결과 제목 링크 후보 점검
- 각 URL마다 고유하고 짧고 구체적이며 실제 내용을 정확히 반영하는 HTML `<title>` 또는 Next.js metadata.title을 확인한다.
- 핵심 주제가 처음에 자연스럽게 읽히도록 배치하고, 필요한 경우만 지역/시장/지표명을 넣는다. 유사 검색어 나열, 중복 단어, 날짜 남발, 과장·낚시성 문구는 금지한다.
- 사이트 브랜드 `ZGMINI` 반복 및 여러 페이지의 동일 title 복제를 피한다. 모바일 표시 폭에 따라 잘릴 수 있으므로 **고정 글자 수만으로 PASS/FAIL 판단하지 않는다**.
- **화면 H1과 SEO title은 역할이 다르다.** 화면 디자인·정보 밀도·자연스러운 표현을 유지한다. 과거 잘못된 사례 `공포·탐욕 (공탐)`처럼 키워드를 괄호로 억지 삽입하는 변경 금지.
- Google 검색결과 제목 링크는 Google이 title뿐 아니라 제목·본문 등 여러 신호로 자동 생성/재작성할 수 있다. HTML title이 반드시 그대로 표시된다고 보고하지 않는다.

## 4. 검색결과 설명문 후보 점검
- URL마다 실제 이용 가치에 맞는 고유한 `<meta name="description">` 또는 Next.js metadata.description을 검토한다.
- 투자자가 궁금한 **무엇을 볼 수 있는지·대상 시장·기간·차트/비교 기능 등 실제 제공 기능**을 평이한 한두 문장으로 표현한다. 설명문을 키워드 목록처럼 만들지 않는다.
- 중복·모호·잘못된 약속을 줄이고, 페이지 본문에 존재하지 않는 지표·데이터 정확도·실시간성·투자 성과를 추가하지 않는다.
- Google은 검색어에 따라 본문에서 스니펫을 자동 생성하며 meta description을 그대로 쓰지 않을 수 있으므로 **본문 첫 설명·섹션 제목·사용자 이해도**도 함께 확인한다.
- `meta keywords` 태그 추가 및 키워드 반복만을 통한 최적화는 하지 않는다.

## 5. 기술·화면 정합성
- SEO 수정 범위에 해당하면 인덱싱 차단(`noindex`, robots), canonical URL, 응답 상태, 메타데이터 중복, 내부 링크 앵커, 모바일에서 제목·본문 가독성을 점검한다.
- 구조화 데이터는 실제 표시 내용과 일치하며 해당 유형의 요건을 만족할 때만 검토한다. 검색 리치 결과를 보장하지 않는다.
- 소셜 공유용 Open Graph/Twitter 문구가 해당 페이지에 이미 있거나 함께 변경하는 것이 타당할 때 검색용 메타데이터와 혼동 없이 정합성을 점검한다.
- 검색결과의 title/snippet 품질 검토는 **대시보드 H1·차트·산식·데이터·DB·Provider·스케줄러·DNS 등을 변경할 포괄적 권한이 아니다**. 지시한 페이지와 변경 범위 안에서 최소 수정한다.

## 6. 매 페이지 작업 체크리스트 · 리뷰 게이트
각 신규/수정 페이지에 대해 아래 사항을 확인하고 PR/상태 기록에 결과를 남긴다.

- [ ] URL·검색 의도·실제 제공 콘텐츠·핵심 검색어 후보 확인
- [ ] HTML/Next.js SEO title 고유성·정확성·읽기 쉬움·화면 H1 분리 확인
- [ ] meta description 유일성·요약 품질·실제 페이지 근거 확인
- [ ] 본문 설명·제목 구조가 실제 스니펫의 소재로 적절한지 확인
- [ ] canonical·index 가능성·중복 경로·내부 링크·모바일 문구 확인(해당 범위)
- [ ] GSC에서 가능한 범위의 노출·클릭·CTR·게재순위 기초값 확인; 없으면 명시
- [ ] 개선 필요 시 **전/후 title·description, 대상 URL, 이유, 검증 방법** 명시
- [ ] 이미 적합하면 `NO_CHANGE`를 기록. 근거 없이 키워드 삽입·문구 변경 금지
- [ ] 변경한 경우 빌드/회귀검사 후 실제 배포의 title/meta/본문을 확인하고, 검색실적과 배포 검증을 별개로 기록

**판정:** `PASS`=해당 URL 점검 완료, `IMPROVED`=실제 메타/본문 개선·검증 완료, `NO_CHANGE`=점검 후 변경 불필요, `PARTIAL`=일부만 확인, `NOT_VERIFIED`=공개 검증 불가. 검색 순위·클릭 성과는 장기간의 검색 콘솔 데이터로 별도 평가.
