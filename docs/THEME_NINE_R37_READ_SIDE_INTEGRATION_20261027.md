# R37: 기존 자동수집 보존형 9개 테마 연결 인수인계 (2026-10-27)

## 확정한 사실

- 기존 Windows PC 수집·저장·계산·게시 작업은 이미 운영 중이다. 별도 신규 스케줄을 설치하거나 동일 자료를 다시 수집하지 않는다.
- 기존 공개 테마 데이터에 2026-10-26 관측일이 이미 표시된다(사용자 확인). R32 개인 계산 시험 원본의 기준일은 2026-10-23이므로 그대로 최신 공개값을 덮어쓸 수 없다.
- R32 개인 시험: 9개 테마, ETF 64개 편입 위치, 서로 다른 ETF 63개, 252거래일 데이터. R33은 과거 공개 결과와의 비교 실험이다.
- R32 시험 소스의 `priceMode`는 `RAW_UNADJUSTED_1H_NOT_OFFICIAL_CLOSE`. 이는 공식 일간 종가라고 표기해서는 안 된다.
- R37은 새로운 수집·산식·일정을 만들지 않는다. R32의 결과를 기존 공개 JSON 필드 형태로 포장해 미래의 *별도* D1 키에서 검증 후 읽는다.

## 구현 파일

1. `scripts/pc-writer/theme-nine-r37-public-candidate.mjs`: 실제 R32 JSON의 버전·로스터·63개 AUM 원본기준일·9×252 점수를 검증한 뒤 **비공개 후보**를 생성하는 순수 함수. API 요청·D1 쓰기·예약작업 수정 모두 0. 승인·권리·가격정합 확인 플래그는 처음부터 `false`이다.
2. `worker/theme-nine-r37-public.mjs`: D1의 기존 테이블 `public_feed_snapshots_v1`에서 **새** `theme-legacy-nine-r37/current`만 선택해 읽는다. 버전, 9개 편입 명세, 관측일, 252일 이력, AUM 날짜·manifest SHA 및 게시·권리·검산 플래그를 모두 만족해야 구버전 9개 점수를 대체한다.
3. `worker/theme-etf-only-public.mjs`: 현재의 기존 공개 조회 루틴(AI/바이오/데이터센터 포함) **뒤에** 새 reader를 추가. 연결 실패·D1 값 부재·검사 실패 시 기존 공개값을 그대로 돌려준다.
4. `tests/theme-nine-r37-bridge.test.mjs`: 실물 R32·R33 파일을 이용한 6개 테스트 PASS. 테스트에서 만든 READY 객체는 실제 게시 권한이 아니다.

## 운영 연결을 위해 아직 필요한 항목 (추정 완료 금지)

1. **PC 계산측**: 실제 실행 중인 `r181-primary-cycle.mjs`, `r179-publish-core.mjs`, `r171-publish.mjs`의 설치 SHA/경로와 변경 승인 파일 확인. R32 개선산식을 **기존 정규 실행**에 병행하되, 신규 스케줄을 만들지 않고 기존 63개 ETF 실제 수집 데이터·계산 가능 여부를 확인한다.
2. **신선도와 가격정합**: 공개 구버전 관측일과 동일한 거래일까지 9×252 개선값을 갱신한다. R32 1시간봉 원가격 기반이라는 점을 검증/고지하여 별도 가격정합 조건이 참일 때만 게시 자격을 준다. 모자란 50개 ETF 자료가 자동으로 있다는 가정 금지.
3. **공개 자격**: 원본 데이터의 상업적 이용·파생 점수 공개 권리 및 점수 산출·manifest 검산을 확인한다. 확인 전 `publicationAuthorized` 등 6개 게이트를 참으로 임의 변경 금지.
4. **저장측**: 승인된 기존 PC 게시기의 **별도** 출력 키로 R37 READY를 1회 저장하고 D1 read-back 확인. 기존 `theme-etf-only-rolling` 및 AI/바이오/데이터센터 키, 과거 이력은 불변. 원자료를 D1에 올리지 않는다.
5. **실배포**: `main` 최신 소스에 검증된 필요 파일만 선택 반영하고 Cloudflare Git 연동·빌드·정확한 배포 SHA·D1/API/UI 확인. 장기간 수정된 migration 브랜치 전체를 main에 병합하지 않는다.

## 현재 상태

**GitHub 지정 작업 브랜치 연결 코드 저장/단위 테스트 PASS. R37 공개 결과 게시와 프로덕션 배포는 아직 아님.** 신규 정규수집 검증은 사용자가 직접 확인한다고 했으므로 별도 반복 요청하지 않는다.
