# R46 수집 → R41 게시 연결 및 라이브 본문 파싱

## 변경 범위

- 기존 7개 출처, R26 PC 메타데이터 보존과 R38 두 단계 키워드 검증을 재사용한다.
- 코드 출처: 뉴스 전용 브랜치 `21cb0c4a503ec4a4d8d65d00751a6c931e19dd01`의 R24/R25/R26/출처 레지스트리 4파일만 선별 복구. 브랜치 전체·추가 4개 매체·번역·AI 분석·UI 변경은 반영하지 않는다.
- 알자지라 `wysiwyg--all-content` 내부의 `<p>`와 `<li>`만 본문으로 읽는다. 전체 페이지·메뉴·관련 기사 영역으로 본문 검증을 대신하지 않는다.
- 원문 제목·발표 시각·본문 접근·키워드 검증을 통과한 14일 기사만 기존 `iran_news_article_metadata_r41`에 monotone UPSERT한다. 본문과 번역·요약은 게시하거나 보관하지 않는다.
- R1 스냅샷, 점수 산식, 기존 과거 원장, 스키마, DNS, Cloudflare Cron을 변경하지 않는다. 새 유료 서비스나 출처를 추가하지 않는다.

## 운영 연결

기존 R13 실행기에서 R29 호출 위치만 R46로 연결한다. 기존 R3·R14·R15 후행 경로와 예약 XML·실행 시간은 유지한다. R29 모듈 및 기존 파일은 삭제하지 않는다.

R46은 기존 PC 데이터 디렉터리와 기존 Writer D1 인증을 사용한다. 수집 종료 시 기존 R29 호환 상태 파일도 갱신하며, 실제 게시 결과는 별도 `news-collect-publish-r46-status.json`에 기록한다.

게시 후 기존 15초 뉴스 감지기가 변경을 읽고 점수 계산을 실행한다. 수집 주기는 기존 6시간을 유지한다. 게시 감지와 원천 수집 주기를 혼동하지 않는다.

## 보존 및 검증

- 일치하는 기존 기사는 재저장하지 않는다. 출처 일부 실패 시 검증된 다른 기사만 게시하며 기존 행을 삭제하지 않는다.
- 빈 응답·전체 출처 실패는 이전 PC 후보와 공개 뉴스를 보존한다.
- 제출 전 pending 메타데이터를 기록한다. 결과가 불명확하면 다음 실행에서 D1 exact readback부터 수행한다. 부분 제출이 확인되면 자동 반복하지 않고 기존 상태를 보존한다.
- 새 행의 ID·URL·제목·발표 시각을 D1과 공개 API에서 대조한다. 공개 API 미확인 상태를 게시 완료라고 보고하지 않는다.
- 기사 라이브 블로그는 여러 사건을 담을 수 있다. 뉴스 목록에 게시됐다는 이유로 전체 블로그를 하나의 확정 사건으로 가감하지 않는다. 기존 점수의 복합 제목·수정 기사 검토 게이트를 유지한다.
