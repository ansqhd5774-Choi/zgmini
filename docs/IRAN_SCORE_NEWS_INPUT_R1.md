# 이란 자동 수집 기사 → 점수 입력 연결

## 범위

R26/R29가 저장한 원문 메타데이터를 기존 R3 분류·중복 판정과 R5 계산에 연결한다.
번역·요약·기사 게시 권한·뉴스 UI·수집기·예약 시간은 변경하지 않는다.
`impact`와 번역 문장은 점수 입력이 아니다. 고정 가중치, 단계 가감점, 기준점,
민감도, 실제 게시별 이력 및 14일 표시 계약을 유지한다.

## 처리

- R26 캐시의 버전·시각·출처/호스트·URL 해시를 확인한다. R29 완료 기록까지 일치할 때만 실제 기사 검증 건수를 신선도 근거로 사용한다.
- 구형 R29 기록에 기사별 검증 통계가 없거나 다른 캐시를 가리키면, 검증된 원문 입력은 사용할 수 있지만 기존 수집 신선도 검사를 대체하지 않는다. 이를 `CACHE_METADATA_ONLY`로 구분한다.
- 7개 출처 중 일부가 실패해도 검증 완료한 기사를 사용한다. 부분 수집을 전체 성공으로 바꾸지 않는다.
- 원문 제목과 발행 시각에서 기존 분류 입력을 만든다. 수집 캐시 갱신 시각을 기사 최초 관측 시각으로 소급하지 않는다.
- 기존 URL은 기존 원본과 관측 시각을 보존한다. 제목 변경은 검토 대상으로 기록한다.
- 새 URL 중 기존 단계 규칙에 해당하고 발행일과 실제 최초 관측일 차이가 0~1일인 것만 기존 불변 원자료 테이블에 추가한다.
- 오래된 신규 기사에는 `OLDER_PUBLICATION_REQUIRES_REVIEW`를 남긴다. 오늘의 새로운 공격이나 과거에 이미 알았던 사건으로 꾸미지 않는다.
- 기존 사건 중복 제거 및 독립 확인 조건은 그대로 적용한다. 전쟁 종결·실제 이행 확인 기준을 낮추지 않는다.
- 메타데이터와 출처 연결 영수증, 내부 처리 체크포인트를 한 트랜잭션으로 저장한다. 입력 실패는 기존 자료를 삭제하지 않는다.
- 점수 계산 신선도는 실제 R29 수집 시각을 사용한다. 로컬 재분류/재실행으로 시각을 연장하지 않는다.

## 운영 연결

기존 R5 예약 실행 래퍼가 동일 lease 안에서 `syncScoreNewsInput(..., {dryRun:false})`를
계산 직전에 실행한다. 정상 새 입력 체크포인트가 있으면 기존 7개 피드 전부 성공 조건에
별도로 묶이지 않는다. 새 입력 사용이 불가능하면 유효한 기존 입력만 사용하고 내부 실행
기록에 정확한 코드를 남긴다. 둘 다 오래되면 기존 게시 차단 동작을 유지한다.

CLI `--preview`는 입력 계획만 검사하며 DB/D1에 입력을 적용하지 않는다.
연결 후 전체 점수 비교는 운영 DB를 복제한 임시 저장소에서 수행한다.
테스트·Git 반영·PC 연결·실제 게시/조회는 별개 검증이다.
