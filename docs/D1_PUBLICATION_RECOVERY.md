# PC 게시의 통신 결과 확인

2026-10-26 14:18KST 게시 검증 실패는 14:21KST 다음 정규 게시에서 복구됐다. 이후 로컬 원장과 D1의 시각·해시 일치, 12 READY를 확인했다. 해당 실패 보고의 상세 항목이 다음 실행에 덮였으므로 직접 원인을 소급 확정할 수 없다. 앞선 실행의 D1_OUTCOME_UNKNOWN은 별도 확인된 사실이며, 이번 실패와 동일하다고 단정하지 않는다.

확인된 구현 문제는 게시 권한 claim/release의 응답 유실 시 처리 결과를 조회하지 않고 종료하던 경로다. claim은 호출당 고유 ID를 사용한다. 일시적 쓰기 오류가 나도 해당 ID와 실제 유효한 lease가 조회되면 실행을 계속할 수 있다. ID가 다르거나 없거나 만료됐으면 성공으로 바꾸지 않는다. release는 기존 ID가 더 이상 소유자가 아님을 조회한 경우에만 해제로 확인한다. 두 경로 모두 같은 쓰기를 자동 반복하지 않는다.

SELECT는 통신/본문 유실 또는 HTTP429/500/502/503/504에만 최대1회 재시도한다. 1초 이상 대기하고 Retry-After가5초를 넘으면 재시도하지 않는다. 인증·SQL·응답 계약 오류는 재시도하지 않는다. 기존60초 요청 timeout,180초 lease,5분 일정,점수/TTL/저장 계약을 변경하지 않는다.

게시 실패 단계·안전한 오류 코드와 READ/WRITE·FETCH/HTTP/BODY·HTTP상태·통신코드를 append-only 사건 기록에 보존한다. 다음 성공 보고로 덮지 않는다. 원문 오류·URL·SQL·본문·키·인증 헤더는 기록하지 않는다. 복구 확인이 되지 않으면 실패·경고를 유지하고 정상 공개본을 보존한다.

격리 검사는 응답 유실 후 실제 반영됨/미반영/다른 소유자/만료, 해제 완료/미완료, 읽기 일시 실패와 지속 실패, 쓰기 무재시도, 인증 실패 및 긴 Retry-After, 실패 증거 보존을 검증한다. fixture 복구와 실제 공급자 장애 복구 증거는 별도로 보고한다.
