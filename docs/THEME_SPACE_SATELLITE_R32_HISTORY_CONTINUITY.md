# 우주·위성 ETF R32 — 실데이터 1년 차트 연속성

## 발생 원인 (2026-10-26)

기존 공개 R1은 252거래일 날짜를 보냈지만 105일만 점수를 표시했다. 저장 데이터의 개별 ETF 산출 가능 일수는 UFO 252일, ROKT 133일, NASA 105일, WARP 79일이었다. R27 계산기가 1개 ETF만 적격인 과거 날짜를 `null`로 처리했고, 2개 ETF가 있더라도 승인된 장·단기 가중치가 성립하지 않으면 `null`로 처리했기 때문이다. 이는 데이터나 이용권 문제가 아니라 과거 합산 규칙의 누락이다.

## 새로운 R32 공개 계약

1. 기존 승인 ETF 명단은 UFO, NASA, WARP, ROKT이며 ETF 수 상한 없음. 개별 종목 사용 금지. 각 날짜는 SPY와 개별 ETF의 실제 저장 가격으로 이미 계산한 `scoreAdaptiveTimeline` 결과만 사용한다.
2. 각 ETF는 해당 날짜 실제 관측 가격이 존재하고, 저장된 검증 세션이 40개 이상이며, `ADAPTIVE_PROVISIONAL` 또는 `R188_COMPATIBLE` 상태이고 0~100의 유효 점수가 있어야 참여할 수 있다.
3. 날짜별 적격 ETF 3개 이상: 현 승인된 `NORMALIZED_DATED_OFFICIAL_AUM`의 **현재 발행사 AUM**을 상대 정규화해 혼합한다. 과거 AUM 보유 현황을 재구성했다고 설명하지 않는다.
4. 날짜별 적격 ETF 2개: 기존 승인 R3 혼합비율(장기 ETF와 단기 ETF의 70:30→50:50 조정 또는 호환 50:50)만 사용한다.
5. 적격 ETF 1개인 날짜, 또는 2개이지만 기존 승인 혼합비율을 적용할 수 없는 날짜: 그 날짜 실제 가격과 점수가 있는 ETF 중 **검증된 관측 세션 수가 가장 많은 ETF** 단독 점수(100%)를 사용한다. 동률이면 현재 검증 발행사 AUM을 비교, 그래도 동률이면 티커 오름차순 결정. 이 규칙은 추정·전일 복사·0점 대체가 아니다.
6. 해당 날짜에 적격 ETF가 전혀 없으면 기존처럼 `null`로 남긴다. 252개 실제 날짜 축, 가격 선택 기준, 40/20/40 세부 축은 변경하지 않는다.
7. 2026-10-23 최신 4종 합산 점수 44.65075를 유지한다. 2026-10-26 PC 사전 로그에서 UFO의 1년 점수 252개와 다른 세 종 개별 실측이 확인되어, 저장자료 기반 재계산 시 과거 단독 UFO 날짜를 복원할 수 있다. 실제 R32 PC 재계산·발행 숫자는 CMD Evidence로 판정한다.

## 배포·원장 보존

- 기존 공개 D1 키 `theme-space-satellite-r1`의 105개 점수·147개 명시 결측은 **그대로 보존**한다. 기존 R1 기록의 점수를 소급 덮어쓰지 않는다.
- R32 전용 키 `theme-space-satellite-r2`, 버전 `THEME_SPACE_SATELLITE_R2_PUBLIC_V1`을 별도 `public_feed_snapshots_v1` 항목으로 발행한다. D1 스키마 변경 없음.
- 새 Reader는 검증된 R2가 존재할 때만 우주·위성의 새 252일 점수로 노출한다. R2 미존재·invalid·stale일 경우 기존 R1 read 경로가 남아 있다.
- 기존 9개 테마의 산식·배치·원자료·DB 키·작업 스케줄러·API 출처에는 변경 없음. 기존 7개 운영 소스 인증을 R31과 동일하게 사용한다.
- 실행 파일 `scripts/pc-writer/theme-space-satellite-r32-publish.cmd`; 텍스트 결과는 같은 위치의 `SPACE_SATELLITE_R32_PUBLICATION_RESULT.txt`로 보낸다.
- GitHub `main` → Cloudflare Production Build 검증 → 사용자 PC CMD → 신규 D1 CAS/readback → 공개 API 확인 순으로 구분한다.
- R32는 **최초 1년 이력 복구** 작업이다. 향후 정규 자동 수집/게시·스케줄러 반영은 별도 승인/검증이 필요하다.
