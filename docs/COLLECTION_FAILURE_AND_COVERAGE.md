## 실패 증거

PC writer 데이터 폴더에 다음 파일을 누적한다. 다음 성공이 앞선 줄을 덮어쓰지 않는다.

- `provider-request-failures.jsonl`: 요청 실패 직후 시각,호스트,FRED의 승인된 계열ID,HTTP/통신 단계,HTTP상태/통신코드. URL·쿼리·키·본문 제외.
- `collection-events.jsonl`: 실행 종료 시 작업·상태·이유·공급자별응답집계·FRED 누락/실패계열·HTTP/통신/페이지시도수·시간. BLS 기존진단도 보존.
- `d1-request-failures.jsonl`: 기존 별도 D1 게시 진단. 수집 로그와 혼동하지 않는다.

FRED가 HTTP503을 반환한 경우와 로컬TIMEOUT/요청cap/인증키누락/빈관측을 구분한다. 실패 본문·오류원문·인증값·원자료는 기록하지 않는다. 진단정보가 없는 과거 실패는 소급 생성하지 않는다. 수집 팝업은 문제 작업명과 확인된 FRED 누락계열 수를 표시한다.

## 표시 계약

최근8일 성공 이력은 그대로 보존한다. 최신 실패가 있으면 과거 성공 이력과 무관하게 경고색으로 표시한다. 최신 확인 증거가 없으면 미확인으로 표시하며, 누락 모니터를 분모에서 빼거나 정상으로 추정하지 않는다. 문구는 `최근8일 성공 n/전체 · 최신실패 n · 최신미확인 n`이며 정상100%를 현재 상태처럼 표기하지 않는다.

테마 보조가격의 private score와 바이오/전력 raw manifest는 최신 HTTP 검증 증거가 아니다. 관측된 과거 수집시각은 성공이력으로 분리할 수 있지만 최신확인은 UNKNOWN이다. 이 수집 모니터가 공개 게시/라이선스 승인/점수 최신성을 증명하지 않는다.

## 신규 작업 추가

- 핵심 수집 작업은 `worker/market-collection-jobs.mjs`를 공유하므로 새 핵심 lane을 모니터에서 따로 누락하지 않는다.
- 별도 수집 lane은 `expanded-collection-health.mjs` 등록ID·근거 파일·성공/실패/무요청 판정 및 UI표시명을 함께 추가한다. 기존 lane의 새 종목/계열/테마 점수는 별도 API나작업으로 중복계수하지 않는다.
- 실제 요청·검증 없이 계산만 재실행한 결과는 성공확인 시각을 갱신하지 않는다. 최초 증거가 없거나 형식이 다르면 UNKNOWN을 유지한다.
- 연구·shadow·과거일회성작업은 운영모니터 분모에 무차별 포함하지 않는다. 등록하지 않은 별도 collector까지 모두 감시한다고 보고하지 않는다.

산식·가중치·관측일·가격계약·저장TTL·DB스키마·스케줄·요청cap 변경 없음. 이번에 불명확한 실패를 가정해 무제한재시도나공급원대체를 추가하지 않는다.
