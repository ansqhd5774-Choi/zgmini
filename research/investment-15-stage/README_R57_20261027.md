# ZGMINI Stage04 R57 — TBRC 유틸리티 단독 재검증

## 목적

R56에서 ⑤ 금융 3/3, ⑥ 유틸리티 2/3, ⑦ 헬스케어 3/3의 보고서 관측이 3회 반복됐다.
⑥의 누락 한 건은 TBRC Utilities 보고서가 내려받아지지 않은 문제가 아니라,
**보고서 본문과 하단 요약표가 서로 다른 전망연도와 성장률을 표시**하는 문제다.

원문: https://www.thebusinessresearchcompany.com/report/utilities-global-market-report

| 검증 항목 | 출처의 원문 값 | 독립 계산 |
|---|---|---|
| 2025~2026 과거 증가 | 7,022.70 → 7,411.11 billion USD; 5.5% | 5.531% |
| 2026~2030 본문 전망 | 7,411.11 → 9,392.75 billion USD; 6.1% | 6.103% |
| 하단 요약표 | 2026 → **2035**; 5.5%, 최종액 9,392.75 | 본문과 양립하지 않음 |

R57은 이 불일치를 지우거나 보고서 자체를 수정하지 않는다.
동일 페이지에 **과거 숫자 2개, 미래 숫자 2개, 기간 2개, 표의 모순**이
모두 드러나고 두 계산이 허용 오차 내 일치할 때만
`NARRATIVE_VERIFIED_METADATA_CONFLICT`로 표기한다.
조건에 맞지 않으면 기존 `SOURCE_AUDIT_INCOMPLETE`를 유지한다.

## 실행 방법 — Windows CMD

1. ZIP 압축을 풀고 `R57_TOPIC06_TBRC_METADATA.cmd`를 더블클릭한다.
2. 기존 PC Node.js, Ollama `gemma3:4b`를 그대로 사용한다.
3. 코드의 오류 사례 검사를 통과해야 실제 수집을 시작한다.
4. TBRC 원문 URL에 **4회 GET**(1회 예열, 3회 측정)하고, 각 회차에 Ollama
   모델이 문서에서 추출된 미래 CAGR 후보를 선택한다.
5. 생성된 다음 3개 파일을 대화에 첨부한다.

   - `R57_TOPIC06_TBRC_METADATA_RESULT.txt`
   - `R57_TOPIC06_TBRC_METADATA_RESULT.json`
   - `R57_TOPIC06_TBRC_METADATA_RESULT_HISTORY.ndjson`

## 제한 및 안전장치

- 최신 페이지에서 직접 읽은 값으로만 판정한다. 기존 결과 숫자는 런타임 입력이 아니다.
- R56의 다른 8개 공급원은 재요청하지 않는다. BRI에도 접근하지 않는다.
- 검색엔진·유료 원문·DB·점수 산식·사이트·배포·일정표를 변경하지 않는다.
- TBRC Utilities 전체 보고서가 **GICS 유틸리티 섹터 전체와 동등함은 입증되지 않았다**.
  따라서 미래 CAGR 6.1%가 다시 검증되더라도 `sector_cagr=null`을 유지한다.
- `NARRATIVE_VERIFIED_METADATA_CONFLICT`는 보고서에 문제가 없다는 의미가 아니다.
  본문 수치를 수학적으로 검증한 별도 관측이며, 출처 메타데이터 오류는 그대로 남는다.
- URL의 리다이렉트·403·429 등이 발생하면 우회하지 않는다.
