## 실행 방법

1. ZIP을 Windows **바탕화면**에 압축 해제한다. `E:`나 `%TEMP%`에 로그를 생성할 필요 없다.
2. 기존 Ollama `gemma3:4b` 실행 상태에서 `R46_TOPIC01_FORECAST_SEARCH.cmd`를 **더블클릭**한다. PowerShell/WSL 불필요.
3. 01 정보기술에 대해서만 4기관×4회(첫 회 예열) 조사를 수행한다. 공식 목록/공개 검색 경로, 공식 보고서 원문, 범위 감사, Ollama 검증과 시간 측정을 기록한다.
4. CMD 옆에 생성되는 `R46_TOPIC01_INFORMATION_TECHNOLOGY_RESULT.txt`를 보내준다. JSON은 추가 분석이 필요할 때 같이 보낸다.

## 판정의 한계와 다음 게이트

- 기관이 403을 반환하면 **해당 실행 중** 추가 동일 접근을 중단한다. 따라서 차단기관의 이후 회차는 정상 검색·원문 검증 속도로 계산해서는 안 된다.
- 공식 카탈로그 접근 성공은 보고서 일치 성공과 다르다. Google/Bing의 HTTP 200만으로 신규 문서 발견 PASS 판정 금지.
- 최종 통과 전 ① 미래 전망 CAGR의 문장·기간 정합성 ② 동등 시장 범위 ③ 미확보/접근 차단 원인 ④ 동일 3회 안정성 ⑤ 출처 이용권을 분리 검토한다.
- R46은 **연구 전용**: 산식, DB, 스케줄러, API, Cloudflare, 배포, 주문 변경 없음. 미확보 값은 0이나 과거 수치로 채우지 않는다.
- **1번 검증 전 2번 및 21개 일괄 실행 금지.**
