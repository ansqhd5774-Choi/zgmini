# R48 정보기술 01/21 — Ollama 후보 선택 및 검색 엔진 격리

작성: 2026-10-27 · 대상 브랜치: `codex/investment-15-stage-m2-r25-20261025`

## R47 실제 PC Evidence

- TBRC 공식 보고서 HTTP 200, `SOURCE_AUDIT=CONSISTENT`.
- 공식 보고서 미래 CAGR: 2026–2030년 **8.3%**, 산술 재계산 **8.276%** (표기 반올림 허용).
- 실제 후보 1개, 유효 인덱스 `0`뿐. Ollama HTTP 200 응답은 `{"index":8,"scope":"PROXY"}`.
- R46의 `OLLAMA_SCHEMA_INVALID`는 **CAGR 8.3과 인덱스 8 혼동**으로 확인. 범위 분류도 원문 제목/범위와 불일치.
- 이 오류 응답을 유효한 수치·분류로 보정해 통과시키지 않는다.

## R48 최소 수정

1. R29 공식 전망치 감사와 미래/과거 구별 로직 유지. 숫자를 AI가 생성하거나 캐시하지 않는다.
2. Ollama에 `index` 숫자 대신 문자열 `candidate_id`를 요청한다. 실제 후보 1개면 JSON 스키마 enum=`NONE`,`C0`만 사용하며 `C0`를 검증한 뒤 내부 index 0으로 변환한다.
3. 모델의 `scope`가 원문 제목과 불일치하면 `SCOPE_REVIEW`로 보존하고 자동 확정하지 않는다.
4. Ollama 실패 시에도 실제 wall time을 기록해 처리 속도를 0ms로 잘못 보고하지 않는다.
5. Google 429는 재시도하지 않지만 Bing의 독립 검색은 계속 수행한다. 한 번 429가 발생한 검색 엔진은 이후 실행 동안 SKIPPED로 구분한다. 인증/우회/유료 검색을 추가하지 않는다.
6. R48은 **정보기술 1개**, 기존 4개 매체, 1회 워밍업 + 3회 본 측정만 수행한다. 과거 R45–R47 로그·코드는 보존한다.

## 단계 통과 게이트

1. Ollama 유효 후보 ID와 모델 scope 기록, TBRC 미래 CAGR 8.3 및 2026–2030 경계 일치.
2. 정보기술 전체 시장과 IT서비스 등 좁은 시장 분리.
3. 네 매체의 시도·HTTP403/429·권리 및 검색 한계를 있는 그대로 기록.
4. 실측 3회 결과·소요시간 반복성(편차 25% 이하) 검사.
5. 모든 소스가 확보되지 않으면 `PARTIAL_*`로 남기고 **2번 주제로 자동 진행 금지**. 속도 검증과 소스 완료 판정을 분리.
