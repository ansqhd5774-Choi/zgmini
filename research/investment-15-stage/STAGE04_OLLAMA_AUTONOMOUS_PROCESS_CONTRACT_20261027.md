'훈련'은 우선 **실제 실패 사례 기반 프롬프트·구조화 출력·검증과 회귀 평가를 개선하는 과정**을 의미한다. 모델 가중치를 실제로 미세조정하지 않은 상태를 `학습 완료`라고 기록하지 않는다. 향후 미세조정이 필요하다면 별도 승인·증거를 갖춘다.

## 2. Stage04 자율 동작 경로

1. 프로그램이 현재 요청 주제와 발행사 허용 목록을 로드한다. R49 기준 연구용 TBRC·SkyQuest·Precedence Research를 유지하고, BRI는 허용 변경 전 요청하지 않는다.
2. 실행 시 발행사 공식 검색을 수행하고 보고서 본문에서 실제 근거를 얻는다. 요청 실패는 발행사별로 기록한다. 오래된 연구 원장을 현행 값의 대체 공급원으로 사용하지 않는다.
3. 출처 처리 코드가 명시된 예상 기간·원시장 규모·전망 본문/표의 수치를 수집하고 내부 모순을 검사한다. 임의로 연도를 고정하거나 전망 숫자를 만드는 행위 금지.
4. 해당 실제 근거만 Ollama에 넘겨 `growth_pct` 숫자와 `metric=FORECAST_CAGR`을 구조화 추출한다. R30에서 확인된 **모델 연도 추측 오류**를 되살리지 않는다.
5. 검증기는 모델 수치와 출처를 대조한다. **모델 출력 불일치**와 **발행사 내부 수치 충돌**을 별도 상태로 남긴다. 둘 다 값은 NULL이나 원인이 다르다.
6. 집계기는 검증된 **서로 다른 출판사** 2개 이상이면 산술평균을 계산한다. 3개 중 1개 미확정이어도 2개가 유효하면 평균 가능하다. 2개 미만이면 미확정·재검토 상태, 점수 0 아님.
7. 매 결과는 원출처 URL·발행사·근거 기간·조회일·모델/프롬프트 버전·검증 판정·집계 구성원·실패 이유를 보존하고 다음 단계가 **코드로 소비할 수 있는 구조화 출력**으로 전달한다.
8. CAGR 전망은 별도 **실제 산업 관측 YoY/가속도**, 기존 **시장심리 F**, 미승인 **G/D/M**과 혼합하지 않는다. 사용자 승인 전 공식 투자매력 순위·점수·운영 게시를 생성하지 않는다.

과도한 병렬·무한 재시도·수동 URL 작성에 의존하지 않는다. 발행사별 타임아웃·요청 횟수·증분 변경 수집·부분 성공 정책은 기존 승인된 실행 계약을 먼저 확인한 뒤 코드에서 제어한다.

## 3. R30에서 이어받는 검증 사실 (완료 상태 정확히 구분)

- 사용자 **Windows R30 실측**: 공식 검색 5/5, 보고서 5/5, Ollama 호출 5/5, **전망 CAGR 유효 3/5**, 발행사 내부 본문/표 충돌 **2/5 `SOURCE_CONFLICT`**. 두 충돌은 모델 오답으로 기록하지 않으며 최종 CAGR 값은 NULL이다.
- R30은 다섯 주제에 대한 **개별 검색/모델 계측기**다. 다매체 자동 수집→유효성 평가→2매체 집계→다음 15단계 입력까지 독립 실행하는 통합 프로그램이 완성되었다는 증거가 아니다.
- R63/R67의 21/21 연구 평균과 R69의 과거 F·산업 활동 병렬 표는 **역사 참고·검증용 시험 입력**으로 보존한다. **R69 CMD 재실행이나 신규 수작업 표 작성은 현재 개발의 선행조건이 아니다.**
- 출처 충돌 2건을 `RESOLVED_BY_MATH` 등으로 통과시키는 정책은 미승인이다. 현행 `SOURCE_CONFLICT` 격리를 유지한다.

## 5. 구현 불변 계약과 금지 사항

- `main`·Cloudflare·D1·PC 스케줄러·공개 API/UI·승인된 공탐/ETF 산식·원본 PDF 15개·기존 데이터·실주문: 별도 승인 전 무변경.
- 기존 R30 동작, 연구 이력, 원장 기록을 삭제·덮어쓰기하지 않는다. 서로 다른 역할의 오류 상태(원문 장애, 모델 오류, 출처 자체 충돌, 권리 미확인, 기간 불일치, 결측)를 하나의 PASS/FAIL로 압축하지 않는다.
- 사용자 PC의 로컬 Ollama 호출과 실제 Windows CMD 로그 없이는 `PC Ollama 실측 완료`로 보고하지 않는다. 개발 호스트 모의 테스트와 운영 실행은 반드시 구분.
- 로깅은 토큰·원문 전문·개인 PC 비밀값을 포함하지 않는 최소 근거 요약만 사용한다. 사용권 미확인 상업적 게시 금지.
- 신규 산식·G/D/M 가중치·투자 순위가 필요해지는 단계는 **사용자 승인 Gate**로 멈추되, 그 전까지의 자료 수집·모델 추출·검증·집계 코드는 계속 개발할 수 있다.

**다음 실행 행동:** R30 관련 소스·테스트를 읽어 P0의 실제 누락 인터페이스를 확인하고, P1부터 Ollama 중심의 자동 처리 코드를 개발한다. 채팅에서 ChatGPT가 직접 결과를 계산·선정하는 단발성 조사를 다음 작업으로 삼지 않는다.
