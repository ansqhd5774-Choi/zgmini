# ZGMINI R47 — 정보기술 01/21 Ollama 응답 형식 단발 진단

- 일자: 2026-10-27 KST
- 기존 작업 브랜치: `codex/investment-15-stage-m2-r25-20261025` (새 브랜치 없음)
- 실행 목적: **R46의 4/4 `OLLAMA_SCHEMA_INVALID` 원인을 실제 모델 출력으로 특정**. 아직 R47에서 성장률을 채택하거나 2번 주제로 넘어가지 않는다.

## R46 PC 로그 분석

- TBRC 원문 감사 `CONSISTENT`가 4회 반복됐지만, Ollama 결과 스키마 검증 오류로 CAGR은 미확정.
- Google은 HTTP 429. R46에서는 Google 429가 다른 엔진 Bing 시도를 막는 오류도 발견했다. R47에서 웹 검색은 하지 않고, 다음 본 측정판에서 엔진별 독립 실패 처리를 고친다.
- BRI는 HTTP 403, SkyQuest는 IT서비스 하위시장, Precedence는 전체 정보기술 CAGR 미확보.
- R46 전체 측정 중앙값 6,584ms, 최대 편차 13.1%는 **정상 수집의 속도가 아니라 진단 속도**다.

## 실행

1. ZIP을 바탕화면에 압축 해제한다.
2. 사용자 Windows에서 기존 Ollama `gemma3:4b`를 가동한다.
3. **`R47_TOPIC01_OLLAMA_DIAG.cmd` 더블클릭**. CMD만 사용한다. PowerShell/WSL/설치/유료 검색 API 없음.
4. CMD와 같은 폴더에 만들어지는 `R47_TOPIC01_OLLAMA_DIAG_RESULT.txt` 파일을 보내준다.

## 이번 진단이 기록하는 항목

- TBRC 공식 보고서 **원문 1회** 재조회, 기존 R29 감사 모듈로 전망 CAGR·시점·금액 검증.
- R46과 동일한 JSON schema 및 동일한 Ollama 모델 요청을 **단 1회** 재현.
- 모델이 반환한 응답 문자열 최대 450자, 필드명, `index` 자료형·범위, `scope` 허용 목록 일치 여부, 모델 계산·로딩·벽시계 시간.
- 원문 전체, API 키, 로그인 정보, 사용자 개인 경로, 비공개 데이터는 수집하지 않음.
- 오류가 발생해도 `DIAGNOSTIC_COMPLETE`를 남길 수 있다. 이는 원인 포착을 의미하지 모델 PASS를 의미하지 않는다.
- 개발 환경 모의 검사 **6/6 PASS**(실제 원문·Ollama PC 응답 검증 전).
