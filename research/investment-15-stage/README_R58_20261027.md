# R58 — TBRC 유틸리티 검증된 수치와 Ollama 범위 분류 분리

## R57 실제 PC 결과

- 공식 TBRC Utilities 보고서 GET: 4/4 성공.
- 원문 본문에서 2026→2030 성장률 6.1%, 금액 역산 6.103%: 4/4 재현.
- 2025→2026 역사 성장률 5.5%, 역산 5.531%: 4/4 재현.
- 하단 표의 2035·5.5% 모순은 4/4 결과에 명시적으로 보존.
- **Ollama 범위 응답이 4/4 `UNRELATED`**, R57은 `MODEL_UNCONFIRMED`.
- 실측 중앙값 1,094ms, 편차 19.6%. 다른 8개 R56 출처는 재수집하지 않음.

이는 모델 응답이 **출처의 숫자를 불러오지 못했다**는 증거가 아니다.
서로 다른 두 판단(검산된 출처의 수치, 모델의 시장 범위 분류)을
한 가지 통과/실패로 합쳐버린 결과다.

## R58 검사 변경점

1. 공식 출처의 숫자 검산과 기간·메타데이터의 일치 여부는 기존 R57의 엄격한
   독립 검산을 그대로 사용한다. 모순이 있으면 메타데이터 표시는 남는다.
2. 검산 통과 시 `source_observed_cagr`에 실제 출처 값을 기록한다.
3. Ollama는 제목·발췌문을 바탕으로 TOPIC 관련성 vs GICS 전체시장 일치성을
   명확히 구분하는 문구로 재실험한다.
4. 모델이 `UNRELATED`를 다시 반환하더라도 모델 응답을 고쳐 쓰지 않는다.
   `SOURCE_VERIFIED_MODEL_SCOPE_DISPUTED` 상태로 남기고
   `model_candidate_id`, `model_scope`, `model_selected_cagr`를 개별 출력한다.
5. 모델이 `PROXY`/`DIRECT`를 반환해도 TBRC Utilities는
   `BROAD_UTILITIES_REVIEW`에 남는다. **섹터 확정 CAGR은 계속 null**이다.

## PC 실행

1. 이 ZIP을 압축 해제한다.
2. `R58_TOPIC06_SCOPE_DIAG.cmd` 더블클릭.
3. 기존 Node.js, Ollama `gemma3:4b`가 동작 중이어야 한다.
4. 소스 GET 4회(예열 1회+측정 3회), 각 회에 모델 분류를 실행한다.
5. 다음 파일을 첨부한다.

   - `R58_TOPIC06_SCOPE_DIAG_RESULT.txt`
   - `R58_TOPIC06_SCOPE_DIAG_RESULT.json`
   - `R58_TOPIC06_SCOPE_DIAG_RESULT_HISTORY.ndjson`

BRI·검색엔진·R56의 다른 보고서·로그인·유료 API·DB·산식·배포에는
접근하지 않는다. 이전 R56/R57 숫자를 다음 실측의 입력으로 사용하지 않는다.
