## 3. 04단계의 두 가지 서로 다른 성장 조사 — 절대 혼용 금지

### 3.1 A: 산업 전망치(`FORECAST_CAGR`) — 독립 매체 조사

목적: 11개 GICS 섹터와 10개 산업·기술 테마의 **미래 산업 전망을 매체별로 비교하는 보조 연구**. 미래 전망 CAGR은 과거 산업 수요 YoY/가속도가 아니며 R2의 실측 성장점수 G를 대체하지 않는다.

유효 매체는 **TBRC / SkyQuest / Precedence Research의 3개**이다. BRI는 R49의 사용자 승인에 따라 `SOURCE_BLOCKED_EXCLUDED`, 네트워크 요청 **0회**. 기관마다 검색·공식 발행사 보고서 URL 조회·Ollama 해석을 독립 수행하고, 다른 기관의 값을 복사하지 않는다.

**각 매체 결과의 최소 필드:** 주제 번호, 표준명, 원문 시장명/포함·제외 범위, 국가·지역, 통화·기준 시장규모와 목표 시장규모(있으면), 성장률 종류, CAGR %, 전망 시작·종료 연도, 공식 URL, 발행/갱신일(확인 시), UTC/KST 실제 조회시각, HTTP·모델 상태, 원문 본문/표/시장규모 재계산 충돌 여부, 이용 허용 범위, `DIRECT/PROXY/SCOPE_REVIEW`와 그 근거.

**3층 보존 구조:**

1. `publisher_observations`: 검증된 매체별 전망치 전체. 하위시장 관측도 범위 꼬리표를 붙여 **별도 표에 보존**하며, 섹터 전체보다 작다고 0점이나 누락으로 처리하지 않는다.
2. `market_group_research_mean`: 같은 실질 시장을 연구한 서로 다른 기관의 수치를 **동일 기관 중복 없이 산술평균**한다. 예를 들어 3%, 4%, 5%의 독립적 전망은 4%. 기간이 다를 때는 기간별 값·산술 참고평균·비교 한계를 함께 표시하고, 동질성 검토/승인 없이 정밀 투자점수로 자동 승격하지 않는다. 서로 다른 세부시장(금융 전체와 리테일 뱅킹 등)은 하나의 평균으로 섞지 않는다.
3. `gics_sector_cagr`: GICS **전체 섹터 시장 범위**라는 별도 입증이 있을 때만 산출 후보. 하위시장 평균이나 Ollama의 `DIRECT` 레이블만으로 만들지 않는다. 입증 전 `null`로 유지하고 위 1·2층의 실물 숫자는 표시 가능하게 한다.

**공정성:** 매체들의 수치가 다르다는 이유만으로 '오류'로 간주하지 않는다. 시장 정의·표본·전망기간의 차이를 설명한다. 반대로 같은 발행사 보고서 안에서 미래 연도·원시 시장규모·CAGR이 서로 양립하지 않는 충돌은 별도 `SOURCE_CONFLICT`로 보존한다. 결측·HTTP 403은 0이 아니다. 발표사 공식 문장만 모델 검증에 사용하며 모델이 원문 수치를 생성하거나 덮어쓰지 못한다. 상업적 데이터 재사용·공개 권리는 별도 Gate다.

### 3.2 B: 실제 산업 성장(`REALIZED_INDUSTRY_ACTIVITY`) — R2의 G 입력

목적: 이미 03단계에서 통과한 테마에 대해 동일 정의·빈도·모집단의 실제 산업 활동값 `X[t]`를 공식 발표에서 확보하고 전년 동기간 성장률 `g[t]`, 변화량 `a[t]`를 산출하는 것.

- 기존 근거: IFR 산업용 로봇 설치, IEA 데이터센터 전력, CPUC 자율주행 운행, FDA 의약품 승인, FedNow 결제량, Eurostat 클라우드 채택, ENISA 보안투자 조사, IAEA 원전, SIPRI 국방비 등. 출처마다 분야·단위·권리와 적용 범위가 다르다. 10번째 우주·위성의 대응 공식 수요 데이터는 별도 확정 대상.
- 공식 발표 링크를 **실행 시 다시 조회**한다. 저장된 수치·HTML·과거 보고서·R63 JSON을 현재 자료로 돌려쓰지 않는다. 원문 이용권·접근 차단을 지킨다.
- 같은 정의·기간 자료가 부족하면 정확한 관측값이나 공표 YoY만 보여 주고 `g`, `a`, `G1/G2/G/M`은 필요한 곳만 `null` 처리한다. 보급률 %p·거래건수 증가율 %·설문 예산 비중을 같은 숫자로 취급하지 않는다.
- R2 설계의 내부 시계열 백분위와 부호 보정은 **후보 방법**으로 유지한다. 서로 다른 산업 원성장률(예: 10% vs 20%)을 곧장 산업 매력도 순위로 사용하지 않는다.

**산식 후보(운영 미승인):** `G=0.60×G1+0.40×G2`, `D=max(0,G−F)`, `M=0.70×G+0.30×D`. 기존 ZGMINI 공탐 F는 가장 최근에 실제 관측한 **유효 잠정치가 있으면 우선**하되 시각·확정/잠정을 표시하며, 기존 ETF 공탐 산식은 건드리지 않는다.

**종료 조건:** 공식 관측 이력과 성장/가속도 검산, 당일 유효 F, 동일 입력 반복 산출, 데이터 부족 격리, 9개 승인 테마 불변, 민감도 비교표가 준비된 다음 **사용자에게 가중치·실운영 여부를 별도로 승인 요청**한다.

**각 주제 실행:** 범위 선언 → 3개 발행사 독립 후보 검색 → 현행 공식 URL GET 및 원문 규모·기간·CAGR 검산 → 기존 Windows Ollama `gemma3:4b` 1회 검증(공유 FIFO 큐 필요 시) → **예열 1회 + 실측 3회** → 매체별 결과·실패·후보 개수·중앙값·편차를 보고 → 사용자 승인 범위 안에서 다음 주제. 외부 호출 20초 제한·무재시도 원칙을 기존 버전 계약에 맞춰 보존한다. 각 반복의 출처를 재조회하며 캐시 수치 복사 금지.

PC 실행 결과 `TXT/JSON`은 Windows CMD 파일과 **같은 폴더**에 생성한다. 403·권리 불명은 우회하지 않고 원인 코드를 기록한다. 과거 시점 CSV/JSON이나 58/63 연구 스냅샷을 새 PC 검증으로 계산하지 않는다.

## 5. 05–08단계 M2 R25 복구 게이트

1. GitHub 전용 브랜치의 `m2/` 코드·`ARTIFACT_INDEX.md`의 원본 ZIP·PDF SHA256과 **사용자 PC에서 실행하는 실제 R25 패키지**를 대조한다. PDF 본문이나 비밀키를 공개 Git으로 복사하지 않는다.
2. R24 Windows 결과의 **원본 15 PDF 15/15 PASS, 평가 0/60, SERV 원문 403**을 기존 사실로 보존한다. R25의 SERV URL 교정은 개발 측 확인만 있으므로 Windows 실측으로 인정하지 않는다.
3. 사용자의 실제 `M2_LATEST_STATUS.txt`로 SERV 및 다른 허용 원문을 검증한다. 403·원문 부재·회사 식별 실패는 별도 `MISSING/BLOCKED` 근거로 남기고 점수 0/탈락과 구별한다.
4. 15개 PDF 원본 해시와 15개 평가 카드 각각의 필드·원본 근거·점수 산식을 독립 검산한다. 자료가 없으면 해당 항목만 보류하고 다른 카드 점수를 임의 상속하지 않는다.
5. **05→06→07→08**의 입력/출력 연결, 같은 입력 재실행의 재현성, 전체 60평가 실패 원인 및 개선 전·후를 검증한 뒤 다음 단계로 진행한다.
