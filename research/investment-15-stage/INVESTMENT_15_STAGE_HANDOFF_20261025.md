## 5. 04단계 R2.0 정량 모델 — 설계안, 실제 계산 전

A. **산업 주지표의 실측 시계열**을 얻는다.

- X[t] = 당기 산업 측정치, X[t−1] = 비교 동기간의 직전 측정치.
- 양(+)의 값인 흐름·설치량·건수·금액: 성장률 g[t] = 100 × (X[t]/X[t−1] − 1).
- 가속도 a[t] = g[t] − g[t−1] (%포인트).
- 클라우드 보급률처럼 %의 비중은 전년 대비 **%포인트 변화**로 따로 표기한다.
- 2년 간격 수치를 1년 YoY처럼 쓰지 않는다. 연율화 시 실제 간격과 방법을 명시한다.
- 분기자료는 가급적 전년 동분기 비교. 계절성과 편입 범위를 확인한다.

B. **각 산업 동일 지표의 과거 기록**을 기준으로 성장률과 가속도의 백분위 점수를 만든다.

~~~text
P(v)=100 × (과거 값 중 현재 v 미만 개수 + 0.5×동률 개수)/과거 표본수
G1 = g > 0 ? 50+0.5×P(g) : 0.5×P(g)
G2 = a > 0 ? 50+0.5×P(a) : 0.5×P(a)
G  = 0.60×G1 + 0.40×G2
F  = 기존 ZGMINI 테마 공탐 점수(읽기 전용)
D  = max(0, G−F)
M  = 0.70×G + 0.30×D
~~~

- G는 산업의 상대적 성장 강도, F는 현재 공포·탐욕, D는 양의 괴리, M은 투자 테마 매력도 제안점수.
- 부호 보정으로 음의 산업 성장이나 음의 가속이 '과거보다 덜 나쁨'만으로 50점을 넘지 못하도록 설계했다.
- 예시: G=80, F=20 → D=60, M=74.0. G=30, F=20 → D=10, M=24.0.
- **이 숫자는 가상 단위 테스트 사례이지 특정 실제 테마의 최신 점수가 아니다.**

**미승인·미검증:** 60:40 및 70:30 가중치, 부호 보정, 백분위 이력의 최소 표본 수, 부적합 대리변수 필터, 비교가능성 및 민감도 검증은 실제 구현 전에 사용자 확인이 필요하다. R2.0에 적혔다고 곧바로 기존 운영에 적용하지 말 것.

**자료 충족률:** 필수 G1/G2/F 중 실제 확보한 개수 ÷ 3 × 100%. 부족한 경우 부분자료 목록에 표시하며, M을 임의로 부분 가중해 완전 정량 결과처럼 나타내지 않는다.

**상태:** QUANTIFIED / PARTIAL_QUANT / PROXY_SCOPE_LIMITED / NOT_YET_RELEASED / RIGHTS_UNCLEAR / BREAK_IN_SERIES / F_STALE / PROVISIONAL 등. 결측을 0 또는 실패로 바꾸지 말 것.

## 8. 실행·운영·권한 경계

1. Windows 사용자가 실행하는 명령은 **CMD만**. PowerShell/WSL/Ubuntu 전제 금지.
2. 기존 ZGMINI의 GitHub/Cloudflare/운영 DB/Provider/스케줄러/공탐 산식/ETF 편입/가중치는 사전 승인 없이 변경하지 않는다.

4. 로그·진단 결과를 만들 때 **CMD 파일과 같은 바탕화면 폴더**에 찾기 쉽게 저장한다. %TEMP% 및 E:의 불필요한 대량 로그 금지.
5. 사용자에게 금지된 미국 증권 규제당국의 API·포털·원문뿐 아니라 **동일 자료를 복제한 우회 경로도 사용하지 않는다**. 다른 허용된 원천만 검토한다.
6. 유료 API 결제·자료 구매·언론 유료 기사 우회 금지. 공개/상업 사용, 데이터 저장·가공·재배포 조건은 분리 확인.
7. Ollama는 정상 작동을 확인한 기존 보조 분석 구성이다. 문서·숫자·원천을 끌어오는 주체로 쓰되 판단 점수는 **결정적 계산 코드**로 재현한다.
8. **NO_TRADE:** 자동주문 API 연결·실제 주문·계좌/인증 정보 취급은 이번 범위 밖. 사용자 수동 실행만 설계.
9. 기존 PDF 15개 산식·가중치와 현재 운영 데이터/테마 이력을 보호한다. 결측을 가상의 과거 데이터나 앞으로의 예정치로 채우지 않는다.
10. 외부 이메일 발송·내부자 문의는 04단계의 기본 작업이 아니며 사용자 명시 승인 없이는 하지 않는다.

## 10. 새 대화에서의 정확한 다음 작업

사용자가 계속 작업을 지시한다면 아래 순서로 진행한다.

1. R2.0 계획서를 **처음부터 끝까지** 읽고 인수인계 내용과 비교한다. 관련 사용자 최신 지시가 있으면 그 지시 우선.
2. 04단계 범위를 고정한다: **기존 통과 테마 9개 대상으로 산업 실측 숫자 조사 + 현재 기존 공탐 점수 참조**. 03단계 ETF 평가와 06단계 기업 재무 실사로 이탈하지 않는다.
3. 9개 산업 원천기관의 *실제 최신 발행 페이지*를 새로 확인한다. 저장된 과거 조사 결과를 현행 수치로 가장하지 않는다.
4. 기관별 **동일 지표의 관측기간·원값·정의·지역·변경기록·이전값**을 확보하고, 성장률·가속도를 먼저 수치표로 제출한다. 회사 주가/ETF 수익률을 산업 성장률로 사용하지 않는다.
5. 숫자가 충분한 테마는 QUANTIFIED 후보, 부족한 테마는 PARTIAL_QUANT/PROXY_SCOPE_LIMITED 등으로 분류한다. 탈락시키지 않는다.
6. 사전등록된 주지표의 편향·결측률과 R2.0 정규화·가중치 60/40 및 70/30의 민감도를 **이제야 검토**한다. 승인 전 운영/공표 순위 없음.
7. 사용자 승인 후에만 정량 랭킹 산식 구현·기존 사이트와 분리된 보고서 작성. 이후 사용자가 선정 테마를 승인하면 05단계로 이동.
8. 이 과정에서 **기사 하나의 진실을 끝없이 재검증하거나 공탐 자체를 감사하는 일**로 되돌아가지 않는다.
