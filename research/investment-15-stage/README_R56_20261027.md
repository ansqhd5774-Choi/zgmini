# ZGMINI Stage04 R56 — ⑤·⑥·⑦ 동시 연구 측정

## 목적

- ⑤ 금융, ⑥ 유틸리티, ⑦ 헬스케어를 **동시에 시작**하는 실제 Windows PC 연구 실험.
- 1회 워밍업 + 3회 독립 측정. 공식 발행사 3곳의 보고서 9개를 **실행할 때마다 새로 HTTP 요청**한다.
- 각 주제는 별도 처리시간·관측 CAGR·전망 기간·시장 범위 및 소스 검사 상태를 가진다.
- Ollama `gemma3:4b`는 공유 직렬 큐를 사용한다. 병렬 주제 처리와 GPU 모델의 동시 실행은 다른 개념이다.
- 기존 `R54` 두 주제 측정과 처리량 차이를 고려하여 성능을 관찰한다. 절대 속도만으로 비교 판정하지 않는다.

## Windows CMD 실행

1. ZIP 전체를 압축 해제한다.
2. Windows에서 로컬 Ollama `gemma3:4b`가 동작 중인지 확인한다. 기존 설정을 바꾸지 않는다.
3. `R56_TOPICS05_06_07_TRIPLE.cmd`를 더블클릭한다. `Node.js` 필요.
4. 다음 세 파일을 대화에 첨부한다.
   - `R56_TOPICS05_06_07_TRIPLE_RESULT.txt`
   - `R56_TOPICS05_06_07_TRIPLE_RESULT.json`
   - `R56_TOPICS05_06_07_TRIPLE_RESULT_HISTORY.ndjson`

실행 중에는 TXT·JSON에 라운드별 진행 결과를 기록한다. 정상 종료 후에는 HISTORY에 본측정의 소요시간과 관측치를 보존한다. 후속 재실행 시 HISTORY에 새 요약을 덧붙이지만, TXT/JSON은 가장 최근 실행으로 교체된다.

## 안전·오류 처리

- TBRC의 본문/메타데이터 CAGR은 기존 R29 감사기로 검산한다. 역사적 CAGR이 미래 표에 혼입된 경우 **양쪽 시장규모 계산이 검산된 경우만** 예외를 허용한다.
- 모델은 공개 보고서에서 문자 그대로 추출한 성장률 후보 ID만 선택할 수 있다. 숫자를 만들거나 신규 출처를 검색하지 않는다.
- URL은 검증한 공식 발행사 페이지로 고정하되 보고서의 **실제 내용은 매 실행마다 새로 수집**한다. 과거 저장 성장률을 새 조사로 포장하지 않는다.
- 접근 제한(401/403/429)을 관측하면 해당 URL을 같은 실행에서 반복 요청하지 않는다. 빈값과 미관측을 `0`으로 대체하지 않는다.
- **BRI 미접촉**, 검색엔진 호출 0건, 구독/유료 PDF 미접근, HTTP 제한 우회 없음.
- 연구 산출물 이외 GitHub 본 코드, 운영 DB/SQLite/D1, 산식, 스케줄러, 공개 사이트, 배포, 주문을 변경하지 않는다.
- 이번 실험은 실 PC 결과가 첨부되기 전까지 **로컬 모의 테스트 통과만** 의미한다. ⑤·⑥·⑦ 실제 데이터 수집 성공은 보고하지 않는다.
